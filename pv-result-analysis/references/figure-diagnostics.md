## 这个库怎么用（先读这段，否则会把它当成结论抄）

**它给的是「候选假设」，不是「现成结论」。** 看到某个形态 → 本库列出**可能**的机制 →
你必须：①回 `hypotheses.md` 认领或新增对应 H-ID；②过**稳健性门槛**（差异是不是噪声）；
③过**反驳门**（有没有别的解释、样本量够不够）。三关都过，才写进 FINDINGS.md 并标"证实"。

**纪律红线**：本库的每一条"可能是 X"都**不能**直接落进 ANALYSIS/FINDINGS/CONCLUSION 当因果。
Stage 3 只写"看到了什么"（形态 + 数字），Stage 4 才用本库把现象**翻译成待验证假设**。
这个库存在的意义，是防止"模型想不到某个机制"而漏诊——**扩大候选集，不是替你下结论**。

**读法**：每张图一节，节内是若干「形态 → 含义 → 候选机制(挂 H-ID/模型) → 怎么调整 → 去哪交叉验证」。
一个形态常有多个候选机制，正确做法是把它们并列成竞争假设、用交叉验证图去区分，而不是挑一个顺手的。

## #5 误差随预报时效（`fig05_horizon_error`）

**这张图产出什么**：over_error `e`（行数, 192）**对所有行按步求 RMSE/bias**，横轴 =
**预报时效 / lead time**（第 k 步 = 起点往后 k×15min，0→191 步 = 0→48 小时）。上图
`rmse_h`（该时效误差大小）、下图 `bias_h`（该时效方向）。竖虚线标 **idx16=超短期 4h**、
橙带标 **[59:155] 短期窗口**。stats.json 落 `rmse_at_ultra_idx`、`rmse_short_window`
（正好对上五口径的 ultra_short / short）。

**和 #6 的根本区别**：#5 横轴是**时效**（离起点多久），#6 横轴是**真实钟点**（time-of-day）。
别混：#5 回答"预报越往后误差怎么长"，#6 回答"一天里哪个时刻误差大"。

判读总纲——**用"是所有曲线都有、还是只有某条"来分离"数据结构"与"模型能力"**：
昼夜包络、远端原料塌这类**共享效应会出现在所有模型曲线上**（是数据/输入性质）；
只出现在个别模型的形态才是**模型架构特异**。这是本节最有用的判别杠杆，反复用。

> **⚠️ 这些是"可能的形态"，不是勾选清单。** 真实曲线可能**都不像**、或只像其中一个。
> 不要硬往某个案例上套——匹配不上就**如实描述你看到的形状、从机制往回推**，
> 并回 `hypotheses.md` 认领或新增假设。本节职责是帮你**检索候选、扩大视野**，不是替你分类。

### 形态 A：误差随时效单调上升

- **代表什么**：正常——气象可预报性随时效衰减。斜率越陡 = 对时效越敏感。
- **候选机制**：有功率惯性/Chronos 先验的模型（M1/M3/M4）近端低、随时效爬升；升幅主要由气象预报质量随时效的衰减决定。
- **交叉验证**：`rmse_at_ultra_idx`（4h）vs `rmse_short_window` vs 48h 三点的差，量化时效敏感度；五口径 Excel 对号。

### 形态 B：曲线近乎平坦（M2 指纹）

- **代表什么**：误差不随时效系统性增长。
- **候选机制**：M2（`PatchRegForecast`）无历史功率惯性、不依赖 Chronos，误差只随气象预报质量走、与"离起点多久"基本无关（→ **H-M2-1**）。可判别预测：M2 在超短期（idx16=4h）相对最差，到 48h 差距收窄甚至反超其他模型。
- **交叉验证**：五口径 Excel 看 M2 是否 ultra_short 最差、48hours 追平/反超；对比其他模型是否近端明显更低。

### 形态 C：近端陡升后趋缓

- **代表什么**：最初几步很准，很快抬到基线后走平。
- **候选机制**：功率持续性 + Chronos 先验只在头几步强，越过"持续性有效窗"后快速失效 → 抬到气象驱动的基线（→ H-CHRONOS-1）。
- **交叉验证**：陡升拐点是否在 idx16 之前；是否 M1/M3/M4 同现而 M2 无（无惯性所以无此陡升）。

### 形态 D（实测子案例）：开头台阶——先低 → 突然抬一档 → 又平滑

穿过一个**边界**的信号。两个竞争解释，**必须区分**：

- **(a) 惯性/Chronos 有效窗到头**：头几步被历史功率持续性 + Chronos 锚得很准（RMSE 低），越过有效窗后跳到气象基线。台阶应 **M1/M3/M4 都有、位置相近**，M2 无。
- **(b) 昼夜包络（夜→日边界）**：若多数行起报时刻集中在夜里/清晨，头几步落夜间 → 功率≈0 → RMSE≈0（白送的准），日出后功率爬起 RMSE 一步跳上去。台阶**所有模型（含 M2）都有**，是数据昼夜结构、非模型能力。
- **怎么区分**：①看台阶落第几步——在 idx16 之前且 M2 无 → 偏 (a)；②台阶所有模型同位置、且和 **#6 的日出跳变对得上** → 偏 (b)（去 #6 看 RMSE 是否也在日出钟点跳）；③看起报时刻是否聚集：每 15min 都有起报 → 昼夜被抹平、更可能 (a)，每天固定时刻起报 → (b) 包络强。
- **怎么调整**：(a) 是信息边界、非缺陷，除非要延长有效窗（更强的近端先验）；(b) 无需调，属正常昼夜结构，只是读图时别把夜间的低 RMSE 当"该时效准"。

### 形态 E（实测子案例）：结尾台阶——最后几步误差突然暴涨

远端边界，**通常指向输入侧退化**。三个候选，**先排伪影**：

- **(c) 样本量伪影（必须先排除！）**：测试集到年底，靠后的行可能凑不满 192 点未来、或 Chronos 尾段缺失 → 尾部几步 `nanmean` 落在**更少、且不同**的样本上，RMSE 虚高（反驳门第 2 条）。**先算每步有效样本量，尾部 n 骤降就是伪影，别归因模型。**
- **(a) 远端原料塌**：48h-ahead 的 NWP 质量本就最差；observe_power_future 是 Chronos 的 192 点，尾段最不可靠 → 依赖它的 **M1/M3/M4 尾部一起涨**（→ H-CHRONOS-1 / H-WXSRC-1 远端表现）。可自算 Chronos 的 observe_power_predicted 尾段对真值误差，看是否与模型尾部暴涨同形。
- **(b) padding 边界泄漏（模型特异）**：M3（`MoiraiPvForecaster`）patch=64、**最后一个 patch 补 32 点 padding**，正好盖远端；M2 也有 padding。若泄漏，尾部暴涨**集中在特定模型（尤其 M3）**，非全体同步。
- **怎么区分**：先排 (c)（看样本量）；再看尾部涨是**全体同步**（→ a 远端原料）还是**只有某个模型**（→ b padding）。
- **怎么调整**：(c) 修数据覆盖/截掉不完整尾段；(a) 远端原料无解则对 48h 段降权使用；(b) 查该模型 padding 的 observed_mask 是否真被忽略。

### 形态 F（实测子案例）：M2 的 RMSE 很"毛"——高频上下抖，别人光滑

- **代表什么**：比"平坦"（B）更细一层——不是不涨，而是**相邻时效步之间没有平滑先验**。
- **候选机制**：M2 是 MLP，"时间信息消失"（全连接无时序归纳偏置），192 输出点之间**无连续性约束** → 逐步 RMSE 剧烈抖；且 M2 输出近似**气象预报形状的直接映射**，**继承了气象预报本身的高频毛刺**（→ **H-M2-6**；H-M2-1 只说"平坦"，毛刺是新的一层）。其他模型有时序结构（PatchTST 日 token / Fourier 基 / Moirai transformer over time）把相邻步平滑掉 → 曲线光滑。
- **关键判别**：**只有 M2 毛、别人光滑 → M2 架构特异，坐实"无时序平滑先验"**；**所有模型都毛 → 是数据/采样噪声**（昼夜包络周期 96 步漏入），非本条。进一步看毛刺周期：**≈32 步 → 撞 M2 的 patch_size=32 边界**；**≈96 步（24h）→ 昼夜包络漏入（作废本条）**。
- **交叉验证**：分模型比曲线光滑度；对 M2 逐步 RMSE 做 FFT/自相关看主周期；与 H-M2 的"误差形态直接跟随气象误差"呼应（可叠 #6/#10）。

### bias 曲线：形态 G / H

- **G. bias 随时效漂移**（近端≈0、远端偏一边）：长时效系统性高/低估——远期预报的方向性漂移。调整：对远端做时效相关的 bias 订正。
- **H. bias 全程偏一边**（与时效无关的整体偏置）：不是时效问题，是尺度/水平问题 → 转 #1 slope、#6 形态 F 查（RevIN 统计量/物理映射）。

### 一个可执行洞察：时效相关的动态加权

B（M2 平坦）和 A（他模上升）的**交叉点**是个动作信号：近端多信有功率惯性的模型、
远端多信纯气象的 M2，**最优组合权重应随时效变**——比固定 ensemble 均值更细，
直接呼应"均值组合是钝器"的 ensemble 边界（→ 图#9 oracle 差距一起看）。

### 读这张图的两个坑

1. **昼夜包络波纹**：48h 跨 ~2 个昼夜（96 步=24h），某些 step 落多数行的夜间 → RMSE 掉到近 0。这**不是"该时效准"，是那个时效对多数行恰好是夜里**。波纹强弱看起报时刻是否聚集；波纹是**所有模型共有**的（据此和 M2 特异的毛刺 F 区分）。
2. **尾部样本量**：靠后的时效步有效样本可能变少（数据尾段不完整），`nanmean` 不稳 → 结论前先看每步 n（见形态 E-c）。

## #6 日内时段误差剖面（`fig06_intraday_profile`）

**这张图产出什么**：按**真实目标物理时刻**（起点 timestamp + 15min×step 还原）聚合，画两条随
time-of-day 变化的曲线——上图 RMSE、下图 **bias = 预测 − 真实**（符号：>0 高估、<0 低估）。
跨全周期、全月份一起平均（不分季节，这是它的口径局限，见末尾"读这张图的三个坑"）。
stats.json 落 `worst_hour_rmse`（最差钟点）、`bias_asymmetry`（`mean_under`=低估平均深度、
`mean_over`=高估平均深度）。

判读的总纲：**RMSE 说"哪个时刻误差大"，bias 说"朝哪个方向偏"。两者要合看**——
高 RMSE + bias≈0 是随机抖动（标定救不了），高 RMSE + bias 有方向是系统偏差（时段化订正就能救）。

### 形态 A：早晚爬坡段 bias < 0（系统性低估）

- **代表什么**：日出后陡升、日落前陡降这两段，预测**跟不上真实的快速变化**，普遍偏小。
- **候选机制**（并列，需交叉验证区分）：
  1. **平滑/滞后**——模型学的是平均行为，对陡升响应被拉平、滞后 → 低估。
  2. **损失往保守值收**——纯 L1/中位数回归（M4，`PatchTSTPvForecaster`）在偏斜的爬坡真值分布上压向低处；追峰激励 M4<M1<M3，故**低估深度应 M4 最深、M3 最浅、M1 居中**（→ **H-LOSS-1**）。
  3. **夜间零值拖累**——模型见过大量"这个钟点=0"，对爬坡边界时刻输出偏保守。
  4. **反向线索**——M3（`MoiraiPvForecaster`）MSE 按 batch 均值归一，低功率时段权重被上调，**早晚爬坡段 M3 反而可能相对更准**（→ H-M3 归一化项，models.md M3 分析节）。
- **怎么调整**：①**时段化 bias 订正**（对该 tod 段减去平均 bias，最便宜）；②爬坡样本在损失里加权；③改损失（L1→加权分位/Huber）。
- **交叉验证**：#1 slope<1（大功率段被压低）呼应；#5 时效曲线爬坡段；**分模型看低估深浅排序是否 M4>M1>M3**（是则支持 H-LOSS-1，不是则另找解释）。

### 形态 B：正午 bias > 0（系统性高估），且多云天更明显

- **代表什么**：正午前后、尤其多云/多云波动日，预测**按晴天峰值锚定**，而真实功率被云遮挡打下去 → 高估。
- **候选机制**：
  1. **辐照输入乐观**——NWP/solargis 抓不住具体积云遮挡时刻，给的辐照偏高，模型照单全收（→ **H-WXSRC-1** 气象来源三角）。这是**输入侧**问题，不是模型的错。
  2. **抹平云的向下高频尖峰**——多云正午功率锯齿抖动，平均映射把向下尖峰抹平 → 均值骑在偏高位置。
  3. **M3 无 NWP 兜底**——M3 气象 100% 押 solargis，solargis 辐照乐观时 M3 正午高估应最重（→ H-WXSRC-1，M4 有 NWP 分通道兜底、M1 十路稀释）。
- **怎么调整**：①**天气型化订正**（按 wclass 分组做 bias correction）；②修输入（补/校准辐照、引 NWP 离散度做不确定性预警）。
- **交叉验证**：#8 分天气型（重点看多云波动/突变组是否高估放大）；#11/#12 查辐照是否漂移/映射位移；#10 NWP 误差分离（前提验证通过后）。

### 形态 C：正午 bias < 0（正午压峰/低估）

- **代表什么**：晴好日正午峰值被**压平**，追峰不足。
- **候选机制**：
  1. **L1/中位数压峰**——M4 条件中位数天然压峰（→ H-LOSS-1）。
  2. **M2 三路等权平均的内生平滑**——temp 头条件均值平滑，推理时把辐照头尖峰按 1/3 抹钝，且**无训练信号纠正**（→ **H-M2-3**，机制已由损失代码证实、净效应待图）。
  3. **Fourier 低频偏置**——M1（`FourierMobaTransformer`）能量集中低频，尖峰表达吃亏（→ H-M1-1）。
  4. **反向**：M3 头级 MSE 追峰最强，正午压峰应**最浅**——若 M3 也明显压峰，反而要怀疑输入而非损失。
- **怎么调整**：峰值加权损失 / 换 MSE 型头 / 峰值段单独订正。
- **交叉验证**：#1 slope<1；分模型压峰深浅排序（预期 M4>M1>M3，M2 另走结构性平均，见 H-M2-3）。

### 形态 D：某时刻 RMSE 高 + bias ≈ 0

- **代表什么**：该时刻误差大但**方向随机**（正负抵消），是抖动型随机误差，不是系统偏差。
- **候选机制**：①该时刻信噪比低（云过境时刻不确定）；②**相位错位**——预测形状对但时刻对不齐，正负误差在均值里抵消（bias≈0 但 RMSE 大）。M3 频域 L1 罚相位、抗这类错位（→ H-M3-1）。
- **怎么调整**：**标定救不了**（没有系统方向可减）。得从输入质量或模型时序建模下手；相位错位要看能否引入更强的时序对齐。
- **交叉验证**：自算各模型预测序列频谱（相位错位会体现在高频）；对比 M3 与他模在该时刻的表现（H-M3-1 若成立，M3 该时刻相对好）。

### 形态 E：某时刻 RMSE 高 + bias 明显偏一边

- **代表什么**：该时刻有**方向性的系统偏差**——好消息，这类可校准。
- **怎么调整**：**时段化 bias correction** 最划算（该 tod 减去平均 bias），比重训模型便宜得多。
- **交叉验证**：`bias_asymmetry` 看偏的方向和深度；与形态 A/B/C 对号入座定位机制。

### 形态 F：整条 bias 曲线**整体抬升或压低**（近平行位移，不是局部）

- **代表什么**：不是"某时刻形状错"，是**尺度/水平层面的整体偏移**。
- **候选机制**：
  1. **RevIN 统计量脱节**——M2/M4 尺度靠历史窗口 mean/var，天气骤变日或扩容/限电后统计量与当日真实尺度脱节 → 整日近等比例尺度偏差（→ **H-M2-4 / H-M2-5**）。
  2. **物理映射变了**——组件衰减/扩容/限电改变了功率-辐照映射，所有模型同时中招（→ #12 判读）。
- **关键区分**：等比例尺度偏差的指纹是 **#1 上 slope 偏离 1 但 R² 仍高**（形状对、尺度错），据此和"形状型误差"分开（→ H-M2-4）。
- **怎么调整**：更新归一化基准 / 尺度订正 / 若是物理映射变化则需重训或重标定，非后处理能补。
- **交叉验证**：#1（slope vs R²）；#12 功率-辐照映射两年是否位移；#11 相关变量分布漂移。

### 形态 G：`bias_asymmetry` 严重不对称（`mean_under` ≫ `mean_over` 或反之）

- **代表什么**：模型整体**保守低估型**（低估深、`mean_under` 大）或**激进高估型**（`mean_over` 大）。
- **候选机制**：L1/中位数偏保守（M4）；MSE 偏追峰、易高估（M3）。
- **业务含义（这条对调度很关键）**：**低估 = 少报可用出力，浪费消纳、影响电量结算；高估 = 虚报出力，调度落空、易触发考核**。两个方向的业务成本不对称。
- **怎么调整**：按业务成本做**非对称加权**（pinball 损失偏向某分位，比如更怕高估就压 q<0.5 的权重），而不是无脑追 MAE 对称最优。

### 形态 H：日出前 / 日落后 bias ≠ 0（夜间本应为 0 却有偏）

- **代表什么**：夜间不发电时段预测**非零**，模型没学到硬零边界。
- **候选机制**：无夜间 mask / 无输出 clip；Chronos 功率先验在夜间给了非零（M1/M3/M4 共享，→ H-CHRONOS-1）。
- **怎么调整**：后处理按太阳高度角/辐照阈值 mask 夜间为 0（几乎零成本、稳赚）。
- **交叉验证**：看非零是否 M1/M3/M4 同现而 M2 无（M2 不依赖 Chronos）→ 指向 Chronos 夜间先验。

### 形态 I：峰前段（约 10–12）bias < 0、峰后段（约 13–16）bias > 0（钟形右偏 / 下午不对称）

- **代表什么**：**不是峰高问题**——穿越零点在太阳正午附近、**正午 bias≈0，追峰其实没错**。出问题的是**日内钟形的对称性/相位**：预测曲线相对真实**偏对称或偏晚**，而真实曲线**偏早达峰、下午被压低** → 峰前欠、峰后超。别把它误读成压峰/追峰（那是幅值轴，看正午单点；这是形状轴，看左右不对称）。
- **候选机制**（并列，需交叉验证区分）：
  1. **温度降额没建模（物理，常见主因）**——真实下午组件更热、效率下降，同等辐照下午出力低于上午；模型若画对称钟形 → 下午系统高估。**未用温度特征（t2m/general_temp）的模型应更重**（→ **H-DIURNAL-1**）。
  2. **对齐 / 时区错位（先排除！）**——预测序列相对真实整体时移几步，天然造成"峰前欠、峰后超"；这是**数据 bug、非模型性质**（反驳门#7）。叠一天 pred/true 看是否整条曲线整体右移。
  3. **相位滞后**——模型对日内变化响应偏慢、钟形拖后（与形态 D 相位错位同源，但此处正负**有系统方向、不抵消**，故 bias≠0）。
- **怎么调整**：先排除对齐；确为系统方向偏差 → **时段化 bias 订正**最划算（峰前段加、峰后段各减自身平均 bias）；根因治理则**补温度降额特征/建模**。
- **业务含义**：**下午系统性高估 = 虚报出力**，调度落空、易触发考核，成本比上午低估更敏感（呼应形态 G）→ **优先修峰后段**。
- **交叉验证**：分模型看下午高估是否集中在**未用温度特征**的模型（→ H-DIURNAL-1）；叠日 pred/true 排除整体时移；#8 **晴天组**此不对称最清晰（多云天被形态 B 的高估掩盖）；读正午 bias 确认 ≈0（坐实是形状而非峰高）。

### 读这张图的三个坑

1. **口径混了季节**——全周期全月份一起平均，同一钟点混了不同季节，季节差异被抹平。想看"6 月正午 vs 12 月正午"需给 #6 加 month 过滤（当前无）。
2. **跨 48h 两天叠在一个 tod 桶**——192 步跨 2 天，同一钟点收到"第一天正午"和"第二天正午"两批点。若 RMSE 双峰或第二天明显更差，其实是**随时效累积**，该转 #5 按 horizon 看，别当日内效应。
3. **bias≈0 不等于准**——正负抵消也会 bias≈0（形态 D）。判断准不准要 bias 和 RMSE 一起看。
