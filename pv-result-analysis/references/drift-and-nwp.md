## 一、分布漂移诊断（跨站：5 训练站 vs 留出测试站雅砻江）

<!-- 2026-07-09 设定变更：旧的"训练集 2024 vs 测试集 2025 跨年对比"作废。现在训练/测试都是 2025，
     漂移是**跨站**的——训练=5 站 pooled（及逐站），测试=雅砻江（不在训练里）。 -->

训练集（5 站 2025）不参与指标计算，用途是回答第一大"为什么"：**留出站雅砻江是不是落在 5 训练站
没覆盖的分布里、最像哪个训练站**。与"NWP 原料差"（下节）、"模型类内能力"（图#8）并列为跨站/月度
变差的候选解释。先重建物理连续序列再统计（见项目背景的重叠推论）。

三类漂移分开查，含义完全不同（"训练分布" = 5 训练站集合，"测试" = 雅砻江）：

| 漂移类型 | 查什么 | 方法 | 查出来意味着什么 |
|---------|--------|------|----------------|
| 特征漂移 | GHI/SSRD/t2m 及 kt、σΔ 的分布，**雅砻江 vs 训练站同月对比**（都 2025） | 分位数/小提琴 + KS 或 PSI | 雅砻江天气模式偏出训练站分布 → 模型在分布外，差是"没见过这个站的这种天"而非"学错了" |
| 标签漂移 | 功率分布、日发电量、日峰值 | 同上；重点看台阶/尺度差 | 雅砻江功率尺度与训练站差（装机/海拔/储能）→ 查 station.md（和熙储能、雅砻江容量），不是怪模型 |
| 映射漂移 | 功率-辐照关系 P(power \| GHI) | 雅砻江 vs 训练站的功率-GHI 分箱曲线叠画 | 曲线位移/弯法变 → 站间物理映射不同（海拔高辐照、组件、限电、储能），所有模型同时受累 |

产出两张图：
- **图#11 同月分布对比图**：关键变量 × 月份网格，**雅砻江 vs 训练站**分布并排，标注 KS p / PSI；
  stats.json 逐月含 psi/ks_p/中位数/p10/p90。
- **图#12 功率-辐照映射对比图**：雅砻江 vs 训练站分箱曲线叠画，差异区间标注。

**标准命令**（`scripts/run_drift.py`；`train_set` 填 5 站 pooled 文件、`true_label` 填雅砻江）：

```bash
python <skill>/scripts/run_drift.py --cols "GHI-solargis,observe_power_future"
# --cols 气象列=特征漂移、功率列=标签漂移；SSRD_pos_* / t2m_pos_* / temp solargis 按 schema 补。
# 逐站对比（找雅砻江最像哪个训练站）：analysis_config.json 里给 "train_stations": {站名: 路径}，
# 脚本会对每个训练站单独跑一遍 vs 雅砻江，输出逐站 PSI 便于排"最像→最不像"。
```

脚本做：`drift_table`（逐变量逐月 PSI/KS → `drift_table.csv`）、`weather_class_drift`（天气型漂移，
kt/σΔ 分布 + 五类占比）、fig11/fig12；给了 `train_stations` 则追加逐站漂移表。

- **三类漂移分别对号**：`drift_table` 气象列 = 特征漂移、功率列 = 标签漂移；`fig12` = 映射漂移。
- **共享基准是天气型漂移的命门（跨站版）**：`weather_class_drift` 用 **训练站的晴空包络与 σΔ 阈值**
  分类雅砻江，否则各自归一化会把"雅砻江整体更亮/更少波动"抹平（`daily_weather_class` 默认 None=自算，
  只适合单站单期；跨站对比必须走 `weather_class_drift`，train 传训练站 GHI）。
- **逐站是新设定的重点**：pooled 会把"很像小壕兔、很不像泗洪"抹成一个平均，务必看逐站 PSI 排序，
  找到雅砻江的**迁移锚**（最像的训练站）与**盲区**（最远的训练站）。
- **结果先落 `drift_table.csv`**，PSI>0.25 的变量进 fig11 细看；结论进 Playbook A。

结论句式："雅砻江 6 月的 σΔ 分布显著偏出训练站（pooled PSI 0.34；逐站看最接近小壕兔 PSI 0.12、
最远离泗洪 PSI 0.51）——高原雨季对流是 5 训练站未覆盖的模式，跨站 OOD 是该月变差的主因。"

## 二、NWP 预报误差分离（条件模块——先验证前提再启用）

思路：同一物理时刻会同时出现在早先行的未来 192 段（当时的**预报值**）和更晚行的历史 672 段
（**事后记录值**）里。两者相减即得 GHI/SSRD 的预报误差序列，不需要任何额外数据。由此可把功率预测
误差分解为“气象原料误差”与“模型映射误差”——“6 月掉是因为气象源掉了”从猜测变成可量化证据。

**前提验证（首次拿到数据时执行，通过才能启用本模块）**：

1. 任选若干物理时刻，把它在所有行里的 GHI/SSRD 取值捞出来（不同行 = 不同提前量）。
2. 数值随提前量变化、并在进入历史段后收敛到稳定值 → 历史段是实况回填，**模块可用**。
3. 处处相同 → 历史段只是预报存档，**模块作废**（NWP 质量只能借道晴天功率做代理评估，间接得多）。
4. GHI-solargis 与 SSRD 要**分别验证**：两者来源不同（卫星产品 vs 数值预报），回填策略可能一个可用
   一个不可用。

验证通过后产出**图#10**：NWP 预报误差月度曲线（按月/按提前量聚合），与功率 RMSE 月度曲线叠画——
两线同步上升即“原料”问题的直接证据。验证结果（可用/作废）记入 FINDINGS.md，避免每次重验。
