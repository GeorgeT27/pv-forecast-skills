对每个模型，归因分析真正用得上的是：它看到了什么特征、没看到什么特征、训练数据覆盖了什么时期。比如"M1 在多云天低估更深"能否归因，取决于 M1 是否用了 SSRD 多点位特征。

## M1 【用户口述 2026-07-07】

- **代码类名**：`FourierMobaTransformer`（2026-07-09 用户提供；pv-model-verify 据此在代码库中定位）
- **模型类型/架构**：Fourier + MoBA + Transformer（在 M4 的 PatchTST 骨架上换掉 tokenizer 与 embedding 层，另加 DoY 嵌入与 VICReg 正则）。管线：
  1. **3 个输入通道**（比 M4 少 2 个）：general_ghi、general_temp、observe_power，各为 历史‖未来预测 拼接 672+192=864（同 M4，功率未来段同样来自 Chronos）。注意此处 general_ghi 的定义与 M4 不同——**GHI_solargis 也并入均值**：SSRD_pos_1~9 + GHI_solargis 十路等权平均（未来预测段同样并入），general_temp 同理十路含 temp_solargis；即 solargis 不再是独立通道；
  2. 切 patch（同 M4：patch=96=一天、不重叠，9 patch/通道）；
  3. **Fourier tokenizer**：预计算的 Fourier 基矩阵，coefficients = basis_matrix @ patch → 每 patch 得 48 个 cos 振幅 + 48 个 sin 振幅；a0=True，额外一行全 1 权重提取 DC 分量（日均值）→ 每通道每 patch 共 **97 维**（96 点的完备基，近乎无损变换，但改变了"什么模式容易学"）；
  4. **通道早期合并**：(B,3,9,97) → (B·9, 291)——每个 patch 的 3 个通道 Fourier 系数拼成一条长向量（对比 M4 的通道混合注意力：M1 在 token 化时就合并通道）；
  5. **DoY 嵌入**：doy → radians=2π·doy/365.25 → [sin, cos] → **零初始化** Linear(2→291) 得 t_emb，expand 到 9 个 patch 后加到 Fourier token 上。零初始化 ⇒ 训练起点是恒等（无季节先验），季节信号强度完全由训练数据学出；
  6. **MoBA（orthogonal Mixture-of-Experts attention）**，替代 M4 的 linear embedding + pos encoding：64 个正交专家，每个专家随机选取 291 维中的 203 维（子集初始化后**固定不变**、不重采样，各专家子集互不相同），各自乘一个**独立不共享**的权重矩阵 W(203→128) + GLU；正交性指 **WW^T ≈ I**（行近似正交归一），由 ortho_reg 软约束——每个专家在自己的特征子空间里做近似等距投影，专家间既看不同的特征子集、又被正则推向互不冗余。专家输出拼接 + 位置编码，跨专家 self-attention 后池化为单向量 → (B·9, 128)；
  7. 骨架：customTSTiEncoder（标准 Transformer，同 M4），序列 = 9 个 patch token × 128 维，flatten head 直接输出单条 192 点预测（同 M4，无分位维度）。
- **输入特征**：general_ghi（SSRD_pos_1~9 + GHI_solargis 均值）、general_temp（t2m_pos_1~9 + temp_solargis 均值）、observe_power；共 3 通道。多点位离散度同样被均值丢弃；且 solargis 与 NWP 集合被混为一路，无法区分来源。
- **损失函数**：loss = λ_main·**Huber** + λ_ortho·ortho_reg + λ_vicreg·VICReg。主损失用 Huber（介于 L1/L2 之间：小误差像 MSE、大误差像 MAE）——与 M4 的纯 L1 不同。
  - **VICReg 细节（2026-07-07 确认）**：两个 view = 同一输入过**整个网络（FourierMobaPatchTST）两次完整前向**，靠不同 dropout mask 产生差异（dropout 位于 MoBA transformer、transformer encoder、flatten head 三处），**无数据增强**。三项全用：invariance（两 view 隐状态相似）、variance（各维 batch std 不低于阈值，γ=1）、covariance（维度间去相关）。**作用位置**：backbone 前向返回 (out, h)，VICReg 施加在 **h = transformer encoder 输出展平的中间表征** (B, patch_num×d_model = 9×128 = 1152)，即 h_a vs h_b——**不作用在最终 192 点输出 out 上**，也不在 MoBA 输出上。**两次前向都算主损失**：梯度 = grad_A + grad_B + grad_ortho + grad_vicreg_A + grad_vicreg_B（Huber 对 out_a、out_b 各算一次，等效双重 dropout 训练；VICReg 只约束中间表征，输出层不受一致性约束）。<!-- 待确认：Huber delta、三个 λ 量级；推理时 dropout 关闭后输出唯一 -->

### M1 架构 → 结果分析含义（推断，结论前需图证）

- **Fourier 表征 → 频域偏置**：平滑的晴天日曲线能量集中在低频少数系数，Fourier token 表达它们极其经济；多云快速波动的能量散在高频系数里，信噪比低。第一机制假设：**M1 在低波动日（晴稳/多云平稳/阴稳）相对更强，多云波动日与 M4 的差距缩小甚至反转**——图#8 天气分型对比直接检验。
- **DC 分量显式化 → 日总量友好**：a0 显式给出日均值，日电量层面（ods_ 口径先按天平均）可能更稳。
- **DoY 嵌入 → 显式"看日历"（跨站设定下双刃更利）**：M1 知道今天是一年中第几天。在**跨站迁移**里这是新的风险点：DoY→季节/太阳高度的映射是**随纬度、海拔变的**，M1 的 DoY 先验从 5 个训练站（江苏平原 + 西北干旱，纬度/海拔各异）学出一个"平均日历"，用到高原留出站雅砻江时，**同一 DoY 在雅砻江对应的晴空辐照基线远高于训练站平均**（4600m 空气稀薄），先验会把模型拉向训练站的季节模式 → 雅砻江特有偏差，尤其季节转换与雨季。可判别：雅砻江某月跨站漂移大（run_drift 逐站）且 M1 变差幅度 > 无日历先验的 M4 → 加分（H-M1-2）。
- **Huber vs M4 的 L1**：Huber 在小误差区像 MSE，对峰值的追踪激励强于纯中位数回归——日内 bias 剖面（图#6）上 M1 的午间低估应浅于 M4；但对突变日大误差的鲁棒性两者接近。
- **通道早期合并 + 专家子采样**：3 通道系数拼接后被 64 个专家各看 203/291 维子集，气象-功率的交互从注意力显式建模（M4）变成专家隐式混合——归因"M1 对某气象通道更/不敏感"比 M4 难，慎下此类结论。
- **VICReg 双 dropout 一致性 → 表征平滑**：invariance 项逼两次 dropout 前向的表征一致，等效对表征做一致性正则；variance/covariance 防坍缩去冗余。预期效果是预测对输入小扰动更稳、相似日之间误差方差更小——图#4/#7 上 M1 的逐日误差波动幅度可与 M4 对比检验；代价是正则过强时可能牺牲对罕见形态（突变日）的表达。
- **与 M4 的同质化基线**：两者共享 patch=一天、Chronos 功率先验（已确认）、相似骨架与 flatten head——图#2 over_error 相关热力图中 M1-M4 相关性预期偏高；若某月相关性骤降，优先查两者 tokenizer 差异能解释的天气型变化。**Chronos 是 M1/M4 共同的单点故障**：若 Chronos 某月变差，两者应同步变差，这反而是排查工具（同步变差 → 查 Chronos；只有一个变差 → 查各自 tokenizer/损失差异）。

## M2 【用户口述 2026-07-08】

- **代码类名**：`PatchRegForecast`（2026-07-09 用户提供并确认拼写；用 "Reg" 而非 M3/M4 的 "PvForecaster"，命名风格不同但已核对无误）
- **模型类型/架构**：纯"气象→功率"映射的 MLP 模型——历史功率序列不进网络，只贡献 RevIN 统计量。流水线：
  1. **历史功率 → RevIN 只取 mean/var**：observe_power 整个 672 历史段（2026-07-08 确认）只用于计算 RevIN 的均值与方差，功率序列本身随后不再进入网络（用户原话 "historical power is useless"）。<!-- 待确认：历史功率的 mean/var 用在哪——输出反归一化？还是也经 stat_embd 拼入特征？（气象自身的统计量已确认走 stat_embd，见第 3 步） -->
  2. **输入 = 三个 category 的未来 192 段预报值**：temp_solargis、SSRD（SSRD_pos_1~9）、GHI_solargis，每个算一个 category；**历史 672 段完全不用**（2026-07-08 确认）；**t2m_pos_1~9 完全不用**（2026-07-08 确认）——温度只吃 solargis 一路。
  3. **气象序列自身也过 RevIN**（2026-07-08 确认）：每个 category 的 192 段先 RevIN 归一化，主干处理的是**归一化后的天气形状**；序列自身的 mean/stdev 不丢弃，经 **stat_embd** 嵌入、拼接到第 4 步 flatten 后的特征后面——尺度信息以统计特征形式注回模型。
  4. **patch embedding**：归一化序列先**左填充 160 个 0** 撑到 352，再按 patch_size=32、stride=32（Patch1d）切成 **11 个非重叠 patch**（2026-07-08 确认，此前口述的 13 为笔误）——(B,192)→pad→(B,352)→(B,11,32)；随后 embedding 32→16 得 (B,11,16)，flatten，**末尾拼接 stat_embd(mean, stdev)**。注意**前 5 个 patch（160/32）恒为全零**，真实预报信息只在后 6 个 patch——左填充疑为工程遗留，不贡献信息。
  5. **每 category 一个专属嵌入 MLP → (B,512)**：SSRD_pos_1~9 九路**各自**过同一个 GHIembedding 模块产生 9×(B,512)，**逐元素相加**合成一个 (B,512)（DeepSets 式集合聚合，2026-07-08 确认），再 LayerNorm，进回归头 MLP。三个 category 的嵌入与回归头**相互独立、不共享权重**（2026-07-08 确认；"GHIembedding"只是 SSRD category 模块的命名，与 GHI_solargis 无关）。由于是 MLP，**时间信息消失**（用户原话，全连接下无时序归纳偏置）。
  6. **输出 192 = 三路预测相加再平均**（2026-07-08 确认）：三个 category 各自出一条 192 预测，等权平均——**M2 内部即"三个单气象源预测器的均值 ensemble"**。<!-- 待确认：输出是否用第 1 步历史功率的 mean/var 反归一化回功率量纲？ -->
- **输入特征**：GHI_solargis（未来 192）、temp_solargis（未来 192）、SSRD_pos_1~9（未来 192×9）；observe_power 历史段仅贡献 mean/var 两个标量。**完全不用 observe_power 未来段 ⇒ 不依赖 Chronos（2026-07-08 确认）**。
- **训练数据窗口**：5 站 2025 联合训练，测试留出雅砻江（全体约定）。

  def compute_loss(self, out_dict, targets):
      loss = 0
      for source_name in self.weather_source_names:      # GHI / SSRD / temp 三路
          loss += self.criterion(out_dict[source_name], targets)   # criterion = MSE

### M2 架构 → 结果分析含义（推断，结论前需图证）

- **Chronos 对照组（2026-07-08 确认）**：M1/M3/M4 全员共享 Chronos 功率先验，M2 是唯一免疫者——**M1/M3/M4 同步变差而 M2 稳 → Chronos 嫌疑坐实；四者全变差 → 嫌疑转向天气/气象原料/数据**。图#2 上 M2 与其他三者的 over_error 相关性应最低，是 ensemble 多样性的最大来源。
- **无功率惯性 → 时效曲线形态独特（图#5）**：其他模型有历史功率/Chronos 先验，近时效误差低、随时效上升；M2 无任何自回归信息，误差随时效应近乎平坦（只随气象预报质量缓慢变差）——预计 ultra_short 口径（index 16=4h）M2 相对最差，48hours 口径差距收窄甚至反超。
- **RevIN 统计量双刃剑**：尺度全靠历史窗口 mean/var——扩容/限电后能较快跟上尺度变化；但**天气骤变日**（连阴一周后放晴）统计量与当日真实尺度脱节 → 突变日（图#8 突变日组）系统性尺度偏差假设。
- **MLP 无时序结构**：日内形状只能由气象预报曲线形状直接携带，模型自身不建模时序依赖——气象预报形状错（云过境时刻偏移）时 M2 无功率惯性可纠偏，图#6 日内剖面上 M2 的误差形态应最直接跟随 NWP/solargis 的误差形态（可与图#10/NWP 模块交叉验证）。
- **形状-幅值解耦（气象 RevIN + stat_embd）**：主干只见归一化后的天气形状，幅值压缩成 mean/stdev 两个标量经 stat_embd 注入——若某月气象源出现**系统性幅值偏移**（如 NWP 辐照整体偏高），M2 的误差应表现为整日近等比例的尺度偏差而非形状错误（图#6 剖面整体抬升/压低、图#1 斜率偏离 1 而 R² 仍高），与形状型误差可区分；这也是 M2 与"幅值直接进主干"的 M4/M1 的又一差异化来源。
- **三路等权平均的内生平滑（损失设计证实此机制）**：loss 对每个头独立算 MSE 求和、从不触及平均后的输出——训练把每个头推向"仅凭本源的条件均值"，temp 头的条件均值注定平滑（接近气候态日形状），推理时等权平均把辐照头的尖峰按 1/3 权重抹钝，且这一拖累**没有任何训练信号去纠正** → 图#1 斜率<1、图#6 正午低估的 M2 特有结构性机制。注意与损失类型排序的交互：M2 头级是 MSE（单头追峰最强，同 M3），但结构性平均反向抹峰——净效应方向待图证，不能直接套"MSE 追峰"结论。反面是稳健性：单一气象源坏掉只污染 1/3 输出。
- **九路"先嵌入再求和"保留 NWP 离散度**：M4/M1 在输入端把 SSRD 九路做算术平均，成员间离散度信息直接丢弃；M2 九路各自非线性嵌入后逐元素求和——非线性下 Σf(xᵢ) ≠ f(mean(xᵢ))，NWP 成员分歧（不确定性信号）部分保留 → **多云/突变天（成员分歧大）M2 相对 M4/M1 可能有独特优势**（图#8 分型对比可验）。
- **气象来源三角中与 M4 同侧**：辐照双源都用（SSRD 九点位 + GHI_solargis；M4 分通道、M1 十路混合、M3 只押 solargis），温度只用 solargis（t2m_pos 不用，2026-07-08 确认）——solargis 辐照单独变差时 M2/M4 受累应轻于 M3；若坏的是 solargis **温度**，M2/M3 温度信息全坏，M4 还有独立 general_temp（t2m 九点均值）通道兜底、M1 十路混合被稀释。

## M3 【用户口述 2026-07-07】

- **代码类名**：`MoiraiPvForecaster`（2026-07-09 用户提供；pv-model-verify 据此在代码库中定位）
- **模型类型/架构**：**预训练 Moirai 1.0 encoder 全量微调** + 线性预测头——与 M1/M4"自训小模型 + Chronos 先验作输入"不同，M3 是把预训练时序大模型本体拿来在场站数据上微调。管线：
  1. 输入 (B, 864, 3)，864 = 672+192 历史‖未来预测拼接（同 M1/M4）；**3 通道 = observe_power、GHI_solargis、temp_solargis**（2026-07-07 确认）——**完全不用 SSRD_pos/t2m_pos 九点位 NWP**，气象只吃 solargis 一路；功率未来段同 M1/M4 来自 Chronos（2026-07-07 确认）；
  2. **切 patch：patch=64 点（=16 小时，不与自然日对齐）**，864/64=13.5 → 每通道 14 个 patch，**仅最后一个 patch 补 32 点 padding** 凑满 64；各通道 patch 摊平进 token 维 → (B, 3×14=42, 64)；
  3. patch 由 64 pad 到 128：**冗余设计**——来自 self.max_patch_size=128，后 64 个位置在 observed_mask 中标 False，transformer 会忽略这些 padding（功能上等价 patch=64，不影响分析）；
  4. 过**预训练 Moirai 1.0 encoder**（d_model=384、num_layers=6，对应 Moirai-1.0-R small 规格；主要模块 MultiInSizeLinear patch 嵌入 + transformer encoder，均在 Moirai 内部），42 个 token 经**跨通道聚合**（2026-07-07 确认"聚合"）→ 输出 (B, 14, 384)；
  5. 线性层投影 → (B, 192)，单条确定性输出（同 M1/M4 无分位维度）。
  - **训练方式：预训练 Moirai 与线性头一起学（全量微调，非冻结）**。
- **输入特征**：observe_power‖未来段、GHI_solargis‖ghi_solargis_predict、temp_solargis‖temp_solargis_predict，共 3 通道。**M3 是唯一不依赖九点位 NWP 集合的模型**（M4 均值用、M1 十路混用、M3 完全不用），气象信息 100% 押注 solargis。
- **损失函数**（2026-07-07 代码确认）：`loss = 0.75 × MSE/mean(target) + 0.25 × |rfft(pred) − rfft(true)|.mean()`
  ```python
  target_mean = torch.mean(target)                       # 整个 batch 的全局均值（标量）
  target_mean = torch.where(target_mean==0, 1, target_mean)  # 防零除（全夜 batch）
  mse_loss = F.mse_loss(logits, target) / target_mean
  loss_auxi = (torch.fft.rfft(logits,-1) - torch.fft.rfft(target,-1)).abs().mean()  # 复数差取模
  return mse_loss*(1-0.25) + loss_auxi*0.25              # 若 loss_auxi_alpha≤0 则纯归一化 MSE
  ```
  1. **MSE 按 batch 均值归一**：均值小的 batch（低功率天/季）损失被放大——防的是"大值主导"，保证小功率时期不被忽视（与用户原话方向核对一致：防大值 dominate）。注意只除均值一次幂而 MSE 随幅值平方增长，是**部分归一化**：大功率 batch 权重仍偏高，只是被压了一档。
  2. **频域 L1 = 复数差的模**：rfft 沿 192 点输出维，直接对复数差取 abs——**幅度和相位都罚**（不是相位不敏感的幅度谱之差），波动"形状对但时刻错位"同样吃罚。
  3. 权重固定 0.75 : 0.25。

### M3 架构 → 结果分析含义（推断，结论前需图证）

- **MSE = 条件均值回归，与 M4 的中位数回归成对照**：MSE 追峰激励最强（M4 纯 L1 < M1 Huber < M3 MSE），日内 bias 剖面（图#6）上 M3 的午间压峰低估应最浅；代价是对坏天离群样本敏感，突变日的极端误差对训练牵引大——图#7/#8 上 M3 在突变日组的 RMSE 尾部是检验点。
- **频域 L1 → 抗过度平滑，且相位敏感**：纯 MSE 的均值回归倾向输出平滑曲线（高频能量偏低），频域项显式要求预测频谱与真值匹配，是对"压平"的直接反制。已确认作用在**复数差的模**上——幅度和相位都罚，时刻错位不豁免（相位型偏差假设作废）。预期 M3 预测曲线的高频含量更接近真值，可对比各模型预测序列的频谱能量分布验证。另注意 MSE 按 batch 均值归一 → 低功率时期（冬季/早晚）被相对上调权重，日内 bias 剖面（图#6）上 M3 的早晚爬坡段或相对更准、按月看冬季月份或相对占优。
- **patch=64=16 小时，不与自然日对齐**：patch 边界在日内漂移（第 1 patch 覆盖 0-16h，第 2 覆盖 16h-32h……），与 M1/M4 的"1 token=1 天"归纳偏置根本不同——日尺度模式需跨 token 学习，但日内快速过程被更细粒度切分。天气分型对比（图#8）中 M3 与 M1/M4 的强弱天气型可能错开，这是 ensemble 多样性的来源之一。
- **预训练先验 + 全量微调**：Moirai 在海量异构时序（LOTSA）上预训练，带来通用时序先验（对 2025 分布外形态可能更稳，图#11 高 PSI 月份 M3 相对变差幅度是检验点）；但全量微调在单站一年数据上有灾难性遗忘/过拟合风险，先验保留多少未知，慎引"预训练所以泛化好"。
- **气象来源三角（M3 独有诊断价值）**：气象输入 M4=solargis+NWP 分列、M1=solargis+NWP 十路混合、**M3=只有 solargis**。某月变差时三者的相对表现可以反解气象原料问题的来源——**NWP 变差而 solargis 正常 → M3 不受影响、M4/M1 受累；solargis 变差而 NWP 正常 → M3 受累最重**（气象敞口 100% 在 solargis）、M4 有 NWP 兜底、M1 被十路均值稀释。可用原始列自算 solargis 与 SSRD_pos 均值各自对真值 GHI 的月度误差来交叉验证。
- **Chronos 依赖链（2026-07-07 确认）**：observe_power 未来段同 M1/M4 来自 Chronos——**M1/M3/M4 全员共享 Chronos 单点**：三者同步变差 → 第一嫌疑 Chronos；且图#2 中 M3 与 M1/M4 的相关性下限由此垫高，ensemble 多样性主要来自 tokenizer/气象源/损失差异而非信息源独立。

## M4 【用户口述 2026-07-07】

- **代码类名**：`PatchTSTPvForecaster`（2026-07-09 用户提供；pv-model-verify 据此在代码库中定位）
- **模型类型/架构**：PatchTST 类深度模型，本质是对 Chronos（预训练时序大模型，用户写作 chronas）功率初步预测的"精调/修正"。管线（各环节 2026-07-07 已确认）：
  1. 5 个输入通道各自为 历史段 concat 未来预测段（未来段来自外部预测，非 M4 任务），每通道总长 672+192=864；
  2. RevIN 实例归一化；
  3. 切 patch：patch=96 点、不重叠 → 每通道 9 个 patch，**1 patch = 整一天**（7 天历史 + 2 天未来 = 9 天）；
  4. linear projection + positional encoding → TSTencoder；
  5. **通道混合注意力**：对全部 45 个 token（5 通道 × 9 patch）做统一 self-attention，同一注意力空间同时建模时间关系与通道（气象-功率）关系——不同于原版 PatchTST 的 channel-independent 设计；
  6. flatten head **直接输出单条 192 点功率**（无分位数维度，不存在"取哪个分位"的问题）。
- **输入特征**（5 通道，均为 历史‖未来预测 拼接）：
  1. general_ghi ‖ general_ghi_predict —— general_ghi = **SSRD_pos_1~9 的九点均值**
  2. GHI_solargis ‖ ghi_solargis_predict
  3. temp_solargis ‖ temp_solargis_predict
  4. general_temp ‖ general_temp_predict —— general_temp = **t2m_pos_1~9 的九点均值**
  5. observe_power ‖ observe_power_predicted（未来段 = Chronos 预测的功率）
  - 多点位信息**只以均值形式进入**：成员间离散度（NWP 空间/集合不确定性信号）被丢弃。
- **损失函数**：error = y_true − y_pred（单条输出），对 q=0.1…0.9 九个分位求 pinball `mean(max(q·e, (q−1)·e))` 后求和。
  **数学等价性（重要）**：同一条预测同时喂 9 个对称分位的 pinball，q 与 1−q 两项之和恒等于 |e|（e>0 时 q·e+(1−q)·e=e；e<0 时对称），加上 q=0.5 项的 0.5|e|，总损失 ≡ **4.5 × MAE**。即 M4 实际是**纯 L1/中位数回归**，分位数形式不提供任何额外信息，也没有输出不确定性区间。

### M4 架构 → 结果分析含义（推断，结论前需图证）

- **Chronos 依赖链**：M4 以 Chronos 功率预测为输入通道之一，若某月/某天气型下 Chronos 先验变差，M4 误差可能被"带偏"——跨月归因时 M4 变差需区分"M4 修正能力下降"vs"Chronos 原料变差"（可对比 observe_power_predicted 与真值的误差月度曲线，与 M4 误差曲线是否同形）。
- **L1/中位数回归 → 条件中位数预测，波动天压峰**：损失等价 4.5×MAE（见上），M4 输出的是条件中位数。在不确定性大的天气（多云波动/突变日），条件中位数天然偏保守、压平峰值；且对大误差的惩罚弱于 MSE 型模型，坏天里的极端误差样本对它的训练牵引小。若 M1-M3 有用 MSE 的，同一坏天 M4 的日内 bias 剖面（图#6）应更偏低估、但逐样本 RMSE 尾部（图#7 坏天）可能更差——这是区分 M4 与他模的第一机制假设。
- **NWP 离散度被丢弃**：SSRD/t2m 九点位只以均值进入。九点位分歧大的时段（通常正是天气不确定的时段）M4 拿不到这个"不确定性预警"信号——若某月九点位离散度显著升高且 M4 相对变差，这是候选解释（离散度可从原始 SSRD_pos_1~9 列自算验证）。
- **RevIN → 对水平漂移稳健、对形态突变不敏感（跨站迁移的护城河）**：实例归一化按样本削掉均值/方差层面的分布差异——**这对跨站尺度差异（不同站装机/辐照基线不同）是天然防护，用 RevIN 的 M2/M4 跨站迁移到雅砻江的尺度层面应更稳**；但突变日的形态变化仍会露出——图#8 天气分型对比中 M4 在"突变日"组的表现是检验点。跨站可判别：若某训练站与雅砻江仅尺度差异（#12 映射平移），RevIN 类模型受损应小于无归一化的模型。
- **patch=一天（非重叠）→ 日尺度模式强、时内细节可能钝**：以天为 token 粒度利于捕捉日间关系，但 96 点内的快速爬坡细节被压进单个 patch，且不重叠切分对日内相位错动不平滑——图#5 时效曲线上爬坡时段误差值得看。
- **通道混合注意力 → 对气象预报质量敏感**：4 个气象通道直接进注意力，NWP/气象源未来段质量差的月份会直接传导（联动 NWP 误差分离模块图#10）。
