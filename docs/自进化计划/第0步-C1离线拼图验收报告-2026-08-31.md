## 拼图结果

确定性规则（H 号 join / 文件路径 / 数值相等 join / 分段表回填字段，无 LLM 推断）拼出：**77 节点、109 边、16 条显式 gap**。gap 不是失败——16 条里 12 条正是"孤儿脚本"缺陷的机器可读证据（plan 无 script 字段 ×4、receipt 无 produced_by ×4、provenance 无 serves ×8，前两类有重叠）。

### 诚实标注

1. **材料差异**：bundle 缺 explanatory_power.json 是打包器的锅不是摊开组的锅（已核实：23 个文件条目只有 .py 没有 .json）。但 Q2 两组都答对了核心问题，此差异不改变排序。
2. **Q1 对图组有构造性优势**：断链在图里是显式 gap 记录，等于开卷考。但这正是论点本身——**图把"需要审计才能发现的缺失"变成了"材料里写明的事实"**；摊开组手里同样有"回执 18 个字段无一指向脚本"的原始事实，它没有去数字段，而是选择了讲一个流畅的故事。
3. **图组的短板**：图节点只带被提升的属性，引不出 verdict_note 原句这类细节（Q3 摊开组更细的原因）；且它汇报的图规模统计数字是错的（报 537 节点/275 边，实际 77/109——小型幻觉，实质内容无虚构）。**启示：图当索引+按需下钻文件的混合模式，优于纯图或纯摊开**。
4. n=1、单弱模型、单 run——这是先导测量不是结论性实验；方向性信号（尤其 Q1 的认识论分野和 2× token/3.6× 时间差）足够支撑进入第 1 步，不足以支撑更强的声称。

## 白捡的发现（进候选改进池）

1. **回执 schema 不统一**：H1/H4 18-19 字段、H3 18 字段（另一形态）、H2 仅 10 字段无 metric_spec/per_seed 明细——最承重的 confirmed 回执反而最薄。第 1 步定 receipt schema 时必须统一 REQUIRED 集。
2. **反思打包器漏关键证据**：build_reflection_input 的选择器把 explanatory_power.json 排除在 23 文件之外（脚本进了、数据没进）。反思器一直在缺这份证据的情况下工作。
3. **数值 join 可作过渡桥**：正式引用字段上线前，历史 run 的图可用数值相等 join 回填相当一部分边。
