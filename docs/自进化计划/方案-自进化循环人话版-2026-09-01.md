# 自进化循环：人话版总方案（2026-09-01）

> 这份文档用大白话把整个方案讲一遍，不带术语轰炸。想看依据和文献编号，去看两份调研文档；想看实施细节，去看 计划-DAG轨迹底座-2026-08-31.md。

## 整件事在干什么

我们有一个"时序诊断技能"（ts-diagnose）：一套教 Claude 怎么做时序模型分析的说明书（playbook）。说明书是人写的，肯定有写得不好的地方。我们想让它**自己变好**：让 agent 拿着说明书去做题 → 看它错在哪 → 找到说明书里导致这个错的那一条 → 改那一条 → 再做题验证改对了没有。

这就是一个循环，和训练神经网络一个道理：跑一遍（前向）→ 找错（反传）→ 改参数（更新）。只不过我们的"参数"是说明书的文字，"反传"要自己设计。

## 第一环：Rollout（做题）——已建成

**考场**：skill-evolve 仓库。**考题**：冻结的评测案例，比如 C1——"PatchTST 和 iTransformer 在 ETTh1 上谁好、好在哪、为什么"，我们事先花 27 次训练把标准答案（gold）做出来冻结了，agent 不知道答案。

**做题过程**：agent 按说明书走完整个分析——先看数据、选路线，然后提假设（"iTransformer 近端差是因为跨变量注意力"这类，每条编号 H1、H2……），设计干预实验（关掉某个开关重新训练，跑 3 个种子），算出结果开"小票"（receipt：改了什么、数字变了多少、用什么口径算的），最后写结论。

**做完题留下三样东西**：
1. **一堆产物文件**（45 个左右）：假设账本、实验计划、每个实验的小票、判决、结论、闸门报告。这是"答题卡"。
2. **转录**：agent 全程说过的每句话、调过的每个工具。这是"考场监控录像"。
3. **埋点事件**：关键动作的时间戳。

**收卷**：脚本自动做三件事——冻结所有产物；从录像里切出"这场考试分几个阶段、每段从几点到几点"（segments.json，一场约 9 段）；然后**拼图**。

**拼图（graph.json）是收卷的核心**。一个脚本把零散的产物按硬规则连成一张关系网：谁生成了谁（这张小票是哪个脚本算出来的）、谁引用了谁（结论引了哪些证据）、谁支持谁（这张小票支持哪条假设）。连接全靠机器可查的证据：假设编号逐字对上、数字位级相等、文件指纹一致。**对不上的绝不硬连，明着记一笔"这里断了"（gap）**——断链本身就是有用的信号。一场 C1 拼出来约 91 个节点、128 条边、21 个 gap。

打个比方：答题卡是一沓散页，拼图就是把每页盖上"谁写的、几点写的、抄了谁"的章，钉成一本有目录的案卷。

**评分**：阅卷人（judge）对照标准答案打分，输出哪条结论对、哪条错。

## 第二环：反思（找错）——当前正在设计实施的部分

题做错了，接下来要回答：**错在哪一步、是说明书哪一条害的**。这是全方案最难的部分，我们的设计分两层。

### 先解决"从哪下手"：锚定

结论错了不能把整场考试都翻一遍（那等于全卷重读）。所以先尽量把错"锚"到具体位置，按从便宜到贵的顺序试：

1. 闸门报告里本来就写了哪条没过 → 直接锚定；
2. 图上有机器可查的异常（断链、数字对不上、种子数不够）→ 锚到那个节点;
3. 阅卷人说"H2 的结论错了" → 顺着 H2 编号，只拉出 H2 这一条线的十来个节点;
4. 都锚不到 → 才让 LLM 看一眼全图鸟瞰卡片，挑一条最可疑的线。

### 第一层：查答题卡（机器为主，能抓大多数错）

沿着图**从错误结论往上游走**，每走到一个节点，问一个问题：**"这个节点声称的东西，用它上游的原料重新算一遍，还对得上吗？"**

- 小票说"关掉注意力后误差变化了 0.00117，用的是前 24 步切片的 MSE"→ 我们拿保留的原始预测文件，按它声称的口径重算。实测能对到小数点后 8 位；如果它实际偷偷用了别的口径，重算值会差 0.08，一眼穿帮。
- 实验计划说"改了 patch_len=96" → 去实验目录读实际的配置文件，看是不是真改了、有没有顺手改错别的。
- 结论引用的数字 → 和小票上的数字位级比对。
- 声称跑了 3 个种子 → 数文件。

**第一个对不上的节点，就是错误的引入点；生成它的那个脚本，就是元凶。**再往下游的错都只是抄错的传播，不用追。整个过程像多米诺骨牌倒着找第一张倒的牌——而且大部分检查是毫秒级的脚本比对，不用 LLM 表态。

为什么坚持机器查而不让 LLM 判？因为文献把"LLM 直读轨迹判哪步错"钉死了：最好的现成方法准确率 14%，轨迹超 90 步接近 0%，2026 年最好的专门方法也不到一半。我们能不用 LLM 判，是因为过去两个月攒下了三样别人没有的东西：每个产物都记着"谁生的我"（链不断）、小票口径写全（声明可比对）、原始预测保留（重算有料）。这三样就是"可以反传"的前提条件。

查不动的地方才升级：数字有随机性 → 补种子重跑（用考场统一的标准评测器重算，不许用考生自己的脚本——否则带 bug 的脚本重放自己的 bug）；实在没法机械化的残余 → 才交给 LLM，且告诉它"其他地方都查过是干净的，只看这几处"。

### 第二层：查思考过程（LLM 上场，处理另一类错）

有一类错第一层抓不到：**每份产物单独看都没毛病，但决策本身蠢**。真实例子：C1 盲跑时 agent"按 z 值最大选分析目标"——选靶文件格式完美、数字全对，但选择标准是错的。错不在纸面上，在脑子里。

这时候动用监控录像（转录）：

1. 图告诉我们可疑产物属于哪一段、**是谁写的**（主 agent 还是哪个子代理——四条假设线是并发跑的，必须切对人的录像，否则把 H1 的思考当成 H2 的现场）；
2. 时间窗掐"它前一个动作结束 → 该产物落盘"，把这一小段录像切出来；
3. LLM 读这段思考现场，找拐错弯的地方。

两条纪律：录像里读出来的只是**线索不是证据**（agent 自述会自圆其说），定罪仍要靠重跑实验验证；同一类决策错误抓到第二次，就把这个决策**产物化**——强制 agent 以后做这个决策时必须落一个结构化文件（候选有哪些、按什么标准选的、为什么淘汰其他），配上闸门。这样这类错下次就升级到第一层，机器直接查。

### 给 LLM 喂料的两条纪律（文献实测教训）

- **扁平装载**：图只在后台负责"挑哪几个文件、按什么顺序排"，挑完把原文平铺给 LLM。不把图结构本身序列化塞进 prompt——实测零增益甚至有害。
- **按信号派活**：不给 LLM 一张"反思问题清单"（实测零增益），而是按错误类型直接派动作——断链→补字段、数字矛盾→重跑、单种子→补种子。

## 第三环：改说明书（更新）——设计已定，待实施

找到元凶后，顺着"这一步是执行说明书哪一条"的链接，把责任落到 playbook 的**具体条款**。然后：

- **一轮只改一处**：改完在冻结题库上重跑验证，分数不升就回滚并记一笔反对票。绝不批量改（文献实测批量改会互相污染，而且三轮激进改写能把能力从 23% 干到 8%）。
- **防练歪**：留一组从不参与改进的保留题（holdout），每轮回归，确保没有为了修 C1 把别的能力改坏；跨轮追踪历史最高分，一跌就警觉。
- **改动记账**：每次编辑记录"改了哪条、哪些题因此翻转"，形成编辑效果的家谱；固化的经验只追加版本，不覆盖重写（覆盖式改写实测会崩）。

## 我们和现有文献的关系（一句话版）

现有的技能自进化方法（SkillOpt、Voyager、ExpeL、GEPA、ACE 等 13 篇核实）全都是"把整场录像摊给 LLM 自己看"——它们行得通是因为任务短（几十步、几千 token）。我们一场 45 个产物、几万 token，正好落在实测"LLM 看不动"的长度档。截至 2026-09，"长任务 → 溯源图 → 机器验证定位 → 只把出事的几页给 LLM → 改说明书"这条完整链，文献里没人做过，三个最近邻各占一块拼图（SGDR 会选段但不会归因、TierMem 有分层下钻但不接进化、MemQ 在图上反传 credit 但靠衰减公式猜而不是重算验证）。

## 现在的进度
