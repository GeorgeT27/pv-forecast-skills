## 4. 案例文件格式

每案例一个目录：

```
eval-cases/<case-id>/
├── artifacts/          # 冻结的 pred/true/config（各变体各种子）
├── case.json           # 机器可读 gold
└── gold-reasoning.md   # 正确思路：最小验证路径（人读+LM judge 对照用）
```

**Holdout 例外**：HT1/HT2/HC1 仅提供 `case.json`，不配 `gold-reasoning.md`。理由：holdout 只服务阶段 3 验证门的通过/降分判定，走**结论层**（脚本匹配 case.json）即可；过程层（LM judge 对照 gold-reasoning）只在迭代集上评。若后续需要在 holdout 上监控过程质量（防"迭代集会走流程、holdout 偷懒"），再补三份 gold-reasoning。

`case.json` 关键字段：`tier`、`injection`（配置 diff）、`gold_component`、`gold_direction`、`measured_signatures`（实测）、`noise_floor_ref`、`verdict_type`（confirmed/refuted/null）、`decoys`（似是而非但错误的归因，评分时命中倒扣）。

## 5. 评分 rubric（供阶段 3 使用）

- **结论层（主分，脚本精确匹配）**：组件/原因指认正确 = 满分；只报指标增减 = 0 分；在 N 类案例上硬指组件 = 负分；命中 decoy = 负分。
- **过程层（次分，LM judge 对照 gold-reasoning.md）**：是否做了切片、是否预登记假设、干预设计是否双向可判、否证后是否诚实报告。
- Tier 2 三条腿完整率单独记录。

### HW1（TSMixer vs TiDE @ Weather pl96）——第一个分布外 Tier 2 案例，已定稿冻结（2026-08-13）

产物：`eval-cases/holdout/HW1/`（slice_measurement.json + prereg.md + case.json + 消融 3 种子 artifacts）。选对理由：两者同为纯 MLP 家族、主要差异即有无通道混合，池化差 0.0205 远超噪声底；干预开关 `--tsmixer_no_channel_mix` 现成。

三条腿实录：
1. **切片**：优势集中在物理耦合簇 p/rho/Tdew/sh/H2OC/VPact（配对 z≤-5，p 达 -20）；horizon 单调递增（h01-24 +0.0017 → h73-96 -0.0432）；孤立通道 wv/OT/VPdef/rh 上 TSMixer 反而小输。
2. **预登记 H1**：池化优势由通道混合 MLP 造成；否证线=消融后仍领先 ≥0.014。
3. **干预判定：H1 否证 + 机理部分成立（对消结构）**。消融池化效应 +0.0025（z=0.5，null）；消融后仍领先 TiDE 0.0180（z=-33.5，原优势留存 88%）→ 池化优势非混合所致。但通道级：耦合簇六通道全部同号受损 27–44%（p +0.0611/18σ），同时 rh -0.0489 / VPdef -0.0177 / OT -0.0114 反向获益——**通道混合是"误差搬运工"：耦合簇受益、孤立通道买单，池化对消**。

**设计级 gold**：统一通道混合是次优设计；药方=按耦合结构选择性/门控混合，而非全局加/去二选一。"域级反号"（ETTh1 有害 vs Weather 有益）弱化为"通道级再分配"——混合价值是通道耦合强度 × horizon 的函数，不是域常数。

开放线程 **W2**：池化优势 0.0180 真因未决（候选：时间 MLP 结构差异、TiDE 的 RevIN/瓶颈）；可用 `--tide_no_residual` 续查。

**待做**：（可选）W2 干预闭环池化真因；用户 PV 真实域案例（等真实数据）。

### 8.1 规则：gold 数字一律脚本生成，禁止手抄（2026-08-17 定为协议）

四处错误的共同根因是"叙述层手工转写"（凭预期下笔、补种子后漏更新、抄错中间值）。自本日起：

1. 写进 case.json / gold-reasoning.md 的**每一条定量声明**（效应量、z、切片值、口径）必须由脚本从冻结产物直接算出并写入，脚本与产出一起存入案例目录（或 scratch 归档路径写进 case 注释）；
2. 人只写**判定与归因逻辑**（verdict、机制叙述、decoy 设计），凡涉及数字，引用脚本产出，不得徒手誊写；
3. 修改冻结产物或补种子后，重跑生成脚本刷新全部关联数字——禁止只改局部；
4. gold 修改治理（轮内冻结、循环只有提案权、重算+用户签字+勘误标记三要件、改后全库回归）依 2026-08-17 讨论执行。
