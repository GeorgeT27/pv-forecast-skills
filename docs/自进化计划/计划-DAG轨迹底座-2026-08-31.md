# 计划：DAG 轨迹底座（2026-08-31）

> 源头：用户提案"一次 rollout = 一张 append-only 类型化 DAG"。
> 评估结论见 调研-轨迹归因与梯度式编辑-2026-08-31.md 末章；本文件只写怎么做。

## 对提案的采纳情况

**核心采纳**：一切 rollout 最终都表示为一张只追加不覆盖的类型化 DAG；timeline/stage/episode/evidence/failure/revision 全部是这张图的投影视图，不另立事实源；回退旧 stage = 追加新版本节点，无环；可变文件引用带 sha256_at_assertion。

**四处修改**：

| # | 原案 | 修改为 | 理由 |
|---|---|---|---|
| 1 | agent 运行时直接画图落盘 | agent 只在产物里填引用字段；收卷时脚本确定性拼图 | C1 实测 agent 自觉机制全失灵（DECISIONS.jsonl 零条、PROGRESS.md 被重写）；字段可用校验器硬闸强制，画图不能 |
| 2 | 有向图 → 做因果分析 | 图只做可达性（blame 候选集、污点传播/作废清单）；因果判定唯一来源=补丁重放 | 共享 LLM 上下文是画不进图的隐藏共因；自报边可能是编的；CAR 本身不建图、全靠 do-重放 |
| 3 | 全套边类型一次上 | 边分两级信任（asserted_by: harness/agent）；informs 类模糊边第一版不做 | 防图膨胀成第二份 transcript；自报边须区别对待且尽量机检 |
| 4 | 跨版本进化总图同期建 | 推后到单 run 图稳定之后 | 跨版本 H 号不对齐，需内容级等价类匹配，未解 |

## 第 0 步：C1 离线拼图证伪（1 天，零破坏，先于一切 schema 定稿）

**做什么**：一次性脚本（放 skill-evolve 或 scratchpad，不进生产），读 C1 rep-01 的冻结产物（45 个）+ segments.json + 转录，按确定性规则拼出 nodes/edges。

**节点最小清单**：Run、SkillSnapshot、各 stage 出口产物、H1–H4（含四拍）、Intervention、Receipt、Verification、Conclusion。三级建档：辅助阅读只挂路径；决定结论成立的建节点；需独立验证/反向定位的必须建节点。

**验收 = 三个已知缺陷变成结构查询**：

1. 孤儿脚本：H1 回执节点应查出缺 produced_by 入边（eval_H1.py 与 receipt 无机器可读链接）；
2. 版图缺失：Conclusion 的 supports 闭包应查不到切片全景表节点；
3. 单 seed 假想注入：receipt 的 n_seeds 一跳可查，descendants(H1-receipt) 给出作废清单。

**判定规则**：三条全中 → 进第 1 步；有查不到的 → 缺口即字段清单，照缺口定 schema 再重跑本步。

## 第 1 步：引用字段 + 拼图进收卷（2–3 天）

> **2026-08-31 完成**。skill-evolve 侧：graph/build.py 正式拼图器（C1 金标 91/128/21 固化进测试）+ graph/query.py + run_blind 收卷自动段抽取/拼图 + DECISIONS.jsonl 机制删除 + 反思打包器补收 explanatory_power.json；10 个冻结 rep 全部回填 graph.json。结果分析skill 侧：produced_by/script/serves 的生产机制此前已在（ablation_verdict --script、plan.script 回填纪律、provenance --serves），本轮补的是 conclusion_gate 规则 5（溯源闭环机检：receipt 完整 schema+脚本指纹相符+seeds≥3+serves 挂回+plan 回填）与规则 6（`## 证据清单` 必带、盘上每张 receipt 必列防摘樱桃），作用域沿用 produces_ablation_receipts flag 零破坏；拼图器同步收割证据清单为 harness 级 evidence_ref 边。两仓测试 108+248 全绿。

1. **产物 schema 加三样**（receipt / intervention_plan / CONCLUSION）：
   - `evidence_refs`：判决/结论引用的文件+条目，格式 (path, selector, sha256_at_assertion)；
   - `governed_by`：本步执行的 playbook 条款标识；
   - 统计元数据：n_seeds / seed 列表 / CI / 噪声底来源（与调研落地项 2 合并，一次改齐）。
2. **校验器硬闸**（不写 playbook 散文）：结论无 evidence_refs → conclusion_gate 拦截；数值结论无统计元数据 → 拦截；参照 rule4 的 frontmatter flag 方式限定作用域，不破坏非 pilot playbook。
3. **graph_build.py 进收卷**：结构化产物 + stage_probe 事件 → 按 H 号/路径/sha 确定性 join → rep-NN/graph.json；join 失败的边显式 fill:gap+why，禁止静默丢。
4. **边信任分级**：观测边（produces/consumes/precedes）标 harness；自报边（supports/refutes/governed_by）标 agent。
5. **免费机检**：supports 边指向的 receipt，delta 符号须与结论方向一致，不一致报结构矛盾。
6. **定位契约**（第 0 步用户评审发现，prototype-v1 已实现）：图头带 `roots` 根目录表（绝对路径只在此出现一次），每个文件类节点存 `locator: {root: <根键>, relpath}` 而非裸路径；产物里抄来的运行时相对路径（如 plan 的 `../phase0/...`）必须在拼图时解析回正典根并落 `exists` 标记 + `ref_as_written` 原文，解析不到显式 gap。这是"图当索引+按需下钻原文件"混合反思模式的前提——反思器拿到节点就能打开文件。
7. segments.json / trajectory.jsonl 保留为拼图原料与投影物化，不改不删。

## 第 2 步：图驱动反思 + 补丁重放（约一周）

1. **反思窗口图化**：失败结论 → ancestors 闭包出候选段 → 候选段装全量，其余段只给一行卡片（段名/时长/出口产物/结局）；build_reflection_input 从"按段全量"改"按图选择性装载"。
2. **补丁重放 v1 只做一种：补 seed 重放**——疑点 receipt 缺多 seed → 补跑 3 seed → 重算下游 → 翻转=定罪、不翻转=洗清。重放所需最小状态 = 该节点 consumes 闭包（带 sha），从图免费得到。
3. **blame 落款**：定罪节点沿 governed_by 边落到 playbook 具体条款 → 进串行接受协议（一轮至多一个跨规则编辑、冻结集验证、不升回滚+DOWNVOTE）。
