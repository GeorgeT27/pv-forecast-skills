# 调研：轨迹表示 × 错误定位 × 梯度式编辑（2026-08-31）

> 三个并行文献检索代理（各 20+ 次检索，全部条目附 URL、逐条核实存在性）的综合。
> 对照对象：阶段 4 已落地的 segment_id+episode_id 轨迹分段、阶段 3 的反思循环（bundle 摊开 → CE-n 批量编辑 → P1-P18 规则户口本）、conclusion_gate。
> 三个问题：①现有分段结构够不够支撑梯度式修改；②如何检测"分析本身错了"并反向定位到 playbook 环节；③如何做最小编辑+选择性反思。

---

## 总判定

1. **分段结构：对"定位"够用，对"定点修改"缺三件东西**——claim→evidence 依赖边、段边界可重启状态、以重放翻转为判据的验证闸。时间轴+阶段标签+序号是必要非充分。
2. **错误定位：让 LLM 直接读轨迹判"哪步错了"被全领域数字判死**（步级准确率 12–34%，部分低于随机）。可行路径 = 确定性 checker 前置 + 补丁重放翻转验证，且最终落点是**规则级**不是步级。
3. **反思方式：全轨迹摊开是被实证打死的反模式**（直接摊开 all-correct 1% vs 结构化定位 24.3%）；批量应用 CE 是"treatment bundle"反模式（无法归因单个编辑）。改法：两段式窗口反思 + diff 式编辑 + 每轮至多接受一个跨规则编辑 + ExpeL 计数器语义。

## 问题一：轨迹分段结构

### 文献版图

**表示格式**。工业事实标准是树形 span 层级而非线性 log：OpenTelemetry GenAI 语义约定（invoke_agent → chat → execute_tool 三层 span，属性键值标签）；LangSmith RunTree 的 `dotted_order`（时间戳+run id 拼进层级路径，一个字段同时表达"第几个"和"在谁下面"）。TRAIL benchmark（arXiv:2505.08638）把错误标签直接挂在 **span id** 上（span id + 错误类别 + evidence + 影响级别）。

**step 怎么切**。PRM 线（PRM800K/Math-Shepherd/OmegaPRM 2406.06592）：step 边界按语义单元切，标签挂在**前缀**上；step 的价值定义是**反事实可达性**（从该前缀 rollout 能否到达正确答案），不是局部对错。OmegaPRM 用**二分搜索找第一错步**（O(log n)），前提是每个前缀可重放估值。反面教训：固定长度机械分块会切断语义边界导致评审误罚（AgentCompass 2509.14647）——**我们按 playbook stage 切段是对的**。

**反事实回放/分叉**（2025-2026 活跃线）：
- **CAR**（Causal Agent Replay, 2606.08275）：把一次 run 建成结构因果模型，对某步做 do-操作后在相同随机策略下向前重执行；预算受限 MC Shapley 把因果贡献分摊到各步。
- **AgentDebug**（2509.25370）：定位最早 critical error（定义=修正后能翻转最终失败的最早步）→ 从该步精确 re-rollout（≤5 次）而非从头重跑。
- **Credit Without Ground Truth**（2608.19760）⚠️关键警告：用 executed replay 当 ground truth 去审计三类廉价 step 信号（LLM judge 打分 / 对数概率比 / 自身置信度），**三者都没超过 shuffle 对照**；隐式 credit 与"流畅度"相关 +0.75 而非真实因果贡献。不做真实重放的"看着打分"式归因测的是流畅度。
- BranchPoint-Latent（2606.14805）：分叉点本身成为一等对象，先打分排序哪些 checkpoint 值得重放。

**与时间轴正交的依赖图**（agent provenance 线，核心主张=时间序 trace ≠ 推理依赖结构）：
- From Agent Traces to Trust（综述 2606.04990）：三层——类型化事件日志 / execution graph（工具调用、记忆操作、claim 间依赖边）/ **evidence–claim support graph**（证据对 claim 是 support/contradict/fail-to-support）。
- **PROV-AGENT**（2508.02866, ORNL）：扩展 W3C PROV-DM（entity/activity/agent）覆盖 agent+MCP，动机就是误差传播追踪。
- **AER**（Agent Execution Record, 2603.21692）⚠️与我们最同构：论点="推理溯源不能从 checkpoint 和执行 trace 事后忠实重建，必须运行时作为 schema 级一等公民记录"；字段含 evidence chain、带修订理由的版本化 plan、结构化 verdict；已在生产 RCA agent 验证。
- 论证图线：QBAF（support/attack 边 + gradual semantics 算 claim 强度，ARGORA 2601.21533）。

**整条摊开 vs 分段喂**：Who&When（2505.00212, ICML 2025）三种阅读策略正面对比——All-at-Once agent 级最好（53.5%）step 级最差（12.5%）；Step-by-Step step 级最好（25.5%）但贵且误差累积；Binary Search 折中。**两级结构（先粗定位到段、再段内细查）天然适配，单一策略不行**。TrajDebug（2608.06346）：错误"显现处≠产生处"（生命周期：产生→传播→显现），纯时间序表达不了跨段传播。

### 对照我们的现状

| 文献要件 | 我们有没有 | 差距 |
|---|---|---|
| 按语义边界分段 | ✅ segment_id=进入序号+playbook+stage | 无 |
| 假设线正交标签 | ✅ episode_id=H 号，四拍横跨多段 | 无 |
| 真时间戳（非 mtime） | ✅ 阶段 4 已删 mtime fallback | 无 |
| 父子/依赖边 | ⚠️ 部分：receipt 溯源四件套 + provenance `serves` 只链了**脚本→episode** | 缺 **claim→evidence 的 support/contradict 边**（结论引用了哪些 receipt/图表/切片表）。没有它，定点修改后无法回答"还有哪些下游结论要作废" |
| 段边界可重启状态 | ❌ | 段入口的输入材料清单、工具输出缓存、随机源记录。这是"从第 N 段分叉重跑"的前提 |
| 版本化修订理由 | ⚠️ ledger 被 stage-3 回填但分不出哪句何时写（阶段 4 已知问题，靠 receipt t_start/t_end 侧面补） | AER 的做法是账本每次修订带 reason 落事件流，而非回写文件 |

**回答问题一：不能完全满足，但缺的不是"换一种分段法"，而是在现有两正交标签上加第三个正交维度——依赖边。** 时间轴（segment）回答"何时何段"，假设线（episode）回答"哪条假设"，依赖边回答"这个结论站在哪些证据上"。三者齐了，"发现某处错→沿依赖边找到所有被污染的下游→只重跑受影响子图"才成立。

## 问题二：检测"分析错了"并反向定位

### 文献版图

**失败归因基准的硬数字**（为什么不能靠 LLM 直读轨迹）：

| 工作 | 方法 | 步级定位准确率 |
|---|---|---|
| Who&When (2505.00212) | 通用 LLM 三种阅读策略 | 12.5–25.5%（agent 级最好 53.5%） |
| TRAIL (2505.08638) | Gemini-2.5-Pro 读整条 trace | 11% |
| TrajDebug (2608.06346) | 错误生命周期+候选集过滤 | 34.1%（vs 直接 prompt 25.7%） |
| AgentDebug (2509.25370) | 逐模块标注+critical error+重放 | 比最强基线 +24%/+17%，下游任务成功率 +26% |
| AgenTracer (2509.03312) | **反事实重放造训练数据 + 8B 专训定位器** | 超 Gemini-2.5-Pro 最多 18.2% |

o1/DeepSeek-R1 也"达不到实用水平"。**共识：LLM 直判是相关性证据，重放翻转才是因果证据**（AgenTracer 把 decisive step 的操作性定义就写成"oracle 替换该步重跑后失败是否消除"）。

**REFLECT**（2606.09071）⚠️专门针对我们这类 silent failure（执行完成、结论看起来对但方法学错）：候选错误步 → 打"诊断补丁"做受控重放 → 用**结果翻转**作对比证据反哺归因；**无 gold 答案时仍可定位**（All-at-Once 55.5% vs REFLECT 76.3%）。

**统计效度类 silent error 的检测**（"没跑多 seed 把噪声当信号"这一族）：
- **Hidden Pitfalls of AI Scientist Systems**（2509.08713）：四类失败——基准选择不当、数据泄漏、metric 误用、**post-hoc selection bias**（挑好看的那次当结果=单 seed 噪声当信号的直系亲属）。核心实证：**看最终报告几乎查不出来，必须审 trace+代码**；结论须强制携带 workflow artifacts。
- **BadScientist**（2510.18003）：research agent 能写出有说服力但不 sound 的论文骗过 LLM reviewer——纯文本层 reviewer 一定被骗。
- AI reviewer 能力边界（2605.20668 等）：统计 rigor 是 AI reviewer 抓到问题最多的类别，但强的前提是**交叉核对结果文件与数字**，不是读报告。
- 可编码成确定性规则的方法学根基：Henderson Deep RL that Matters（1709.06560，seed 方差可翻转结论）、Colas How Many Random Seeds?（1806.08295，**所需 seed 数的功效分析公式**）、Miller Adding Error Bars to Evals（2411.00640，标准误+配对分析）、AdaStop（2306.10882，自适应序贯检验）。
- MAST（2503.13657, NeurIPS 2025）失败分类学把 **task verification 缺陷单列为一等类别**——"没做验证"应在我们的 failure_type 词表里独立成类，与规则误导/执行失误分开统计。

**从"结论错"反推"规则错"（clause-level blame）**：
- **aPSF**（2604.06699）：整体式 prompt 编辑"耦合组件、模糊 credit assignment"；做法=prompt 因子化后做**干预式单因子更新**，用验证集性能变化估计每个因子的边际贡献——条款级消融归因。
- STAMP（2607.11172）：provenance-guided credit assignment，用产物溯源链决定 credit 流向。
- CANTANTE（2605.13295）：同一 query 不同参数化多次执行做对比归因。

### 对我们的具体方案（按"没跑多 seed"走一遍）

**检测三层，越靠前越确定性，LLM judge 永远不当第一道**：

1. **确定性 checker（conclusion_gate 扩展）**：这不是需要智能才能发现的错误，它在轨迹里是一个**可机检的字段缺失**——数值型结论没有伴随 n_seeds≥k / CI / Δ 相对噪声底的效应量。规则可直接从 Colas/Miller 公式编码：任何"A 比 B 好"型 claim 若 n_runs=1 或 |Δ| < z·SE_seed → BLOCKED。我们已有 noise_floor_3sigma 和三种子协议，缺的是把它从"playbook 指令"升级为"receipt 强制字段 + gate 机检"。
2. **checklist 型 reviewer 第二层**：喂结果文件路径让它交叉核对数字，不是喂 FINDINGS 文本（Hidden Pitfalls/BadScientist 的教训）。
3. **失败分类**：verification-missing 在 failure_type 词表里独立成类（MAST），跨案例计数才能看清 playbook 缺陷分布。

**定位：两级检索 + 补丁重放**：
- 先段级粗定位（我们只有 12 段，候选集天然小，等价 TrajDebug 的 candidate-set 过滤——不需要 CAR 的全量 Shapley）；
- 疑点段做 **REFLECT 式补丁重放**：在该段插入缺失的验证步（补跑 3-seed），重放下游，**结论翻转 → 该环节确认为 blame，证据是因果的**；不翻转 → 洗清。
- 最终落点**规则级**：同一缺陷跨轨迹在同一 playbook 环节复现 → aPSF 式单条款干预（加"多 seed 验证"条款）在失败案例集上对比重跑 → blame 从"这条轨迹第 7 段"上升为"attribution playbook 缺第 X 条"。这直接接上 CE/规则户口本。

**轨迹记录侧要补四件**：
1. receipt 强制统计元数据字段：n_runs / seed 列表 / CI / 噪声底来源——缺失本身即 gate 信号；
2. **negative evidence 显式记录**：跳过的验证步 + 理由（`skipped: single checkpoint available`），让 checker 能区分"没做"和"没记"；
3. 段入口状态快照 + 随机源记录（重放的前提）；
4. 溯源链反向可走通：从错误结论一步查到产出它的段与其输入（问题一的依赖边，两处是同一件事）。

## 问题三：梯度式最小编辑 + 选择性反思

### 文献版图

**编辑粒度**。TextGrad/ProTeGi 的 textual gradient 实际是"批评→整段重写"，粒度控制不在编辑侧。显式做局部编辑的：
- **GRIPS**（2203.07281, EACL 2023）：指令切短语，delete/swap/paraphrase/addition 四操作，打分集不升不留（=编辑回滚）。
- **LPO**（2504.20355, NAACL 2025 Oral）⚠️最接近"梯度式最小编辑"：先让 meta-prompt 在原文里打 `<edit>` 标签圈出可编辑区域，Proposal LLM **只许改标签内**；可插件式套在 APO/OPRO 上，效果更好且**收敛更快**。
- **SMCEvolve**（2605.15308）：编辑粒度做成可调轴——diff（SEARCH/REPLACE 补丁）vs rewrite。
- ACE（2510.04618）delta 语义核实：新 id bullet 追加、已有 id 原地更新；正文**没有**显式 ADD/UPDATE/DELETE schema（开源库里才有），每轮 delta 数量无上限，**计数器如何驱动淘汰正文也没写**。后续 MCE（2601.21557）用 agentic skill evolution 搜索 CE 流程本身，报告再 +18–33%（细节需精读）。

**最小改动偏置**：
- **POaaS**（2603.16045）最显式的工程化：drift 约束 D(x,x′) ≤ 0.08–0.15（编辑距离 cap）、关键内容保全罚项、**conservative skip gate**（现状达标就不改，"宁可漏改不可误改"）。反面证据：全量重写式 APO 在小模型上把 BBH 从 42.2% 打到 10.4%。
- **Edit-Level Causal Analysis**（2605.26655）⚠️one-change-at-a-time 的最直接实证：对 DSPy/TextGrad/GEPA 共 1.9 万+ 真实修订对做 IPTW 因果分析，发现优化器每步同时改多个特征（**treatments are bundles**）→ 无法归因单个编辑效果。
- prompt 文本上的显式 trust-region 形式化**未检索到**（明确空白）；POaaS δ-cap 是最接近的工程替身。MAPO（2410.19499）把动量引入 textual gradient。

**选择性反思**：
- **AgentDebug 的对照数字是"全摊开"的死刑判决**：Direct Prompting（全轨迹摊给 LLM 判错）all-correct **0.3–1.0%**，AgentDebug 结构化两段式 **24.3%**；step 定位 28→45%；下游 ALFWorld 21%→55%。
- REFLECT：诊断器只收"**正确前缀 + 错误步 + 级联窗口**"，不收全轨迹。
- **H²R**（2509.12810）分层记忆：高层卡片（任务、子目标序列、规划洞察）+ 低层（子目标、轨迹段、执行洞察）；消融去高层 −27.7%、去低层 −19.4%。
- Reflect-R1（2606.27922）：不给新证据的纯内省反思**反而降准确率**——反思必须锚定选择性检索到的证据。
- 检索式反思一族：ReasoningBank（2509.25140, Google）、MemR³、ARC。

**规则级信用记账**：
- **ExpeL**（2308.10144, AAAI 2024）⚠️规则户口本的现成机器语义：insight 池四操作 **ADD/EDIT/UPVOTE/DOWNVOTE**；新规则 importance count 初始 **2**，UPVOTE/EDIT +1、DOWNVOTE −1、**归零自动删**。比 ACE 的 helpful/harmful 双计数更完整（ACE 没写淘汰规则）。
- Dynamic Cheatsheet（2504.07952）：LLM 判断式 curation，无数值计数器——比 ExpeL 粗。

**多候选编辑排序**：GEPA Pareto 前沿是用来选"从谁继续变异"，不解决"一轮 N 个编辑先应用谁"；ProTeGi 用 bandit best-arm 在 minibatch 上串行选择。**"批量编辑的冲突检测/影响面排序"没有成熟文献（明确空白）**，参数级 knowledge editing（MEMIT-Merge 2502.07322）只能类比。

### 对我们的具体方案

对照现状（反思=按段 bundle 摊开 → 一轮出一批 CE → 人工规则户口本 P1-P18）：

1. **反思改两段式**：第一段便宜审计只输出"候选错误段 + 置信度"（我们 12 段候选集小，段级判别远易于步级）；第二段反思器只收**正确前缀摘要 + 错误段全量 + 下游级联窗口**，其余段只给 H²R 式高层卡片（段名、时长、出口产物、结局一行）。阶段 4 的按段 bundle 已是正确地基，下一步是从"按段组织的全量"变成"按段选择性装载"。
2. **CE 批量应用是 treatment bundle 反模式**（round-1 一次应用 CE-7~17、round-3 一次 CE-18~24 都属此列——P 计数已被污染的风险真实存在）。修正：批量**生成**保留，但 minibatch 验证门**串行接受**——每轮至多接受一个跨规则编辑；同一规则内的多处编辑才允许捆绑。接受协议：单编辑应用 → 冻结集（C1-C3/Tier1 子集）重跑 → 不升即回滚并记一次 DOWNVOTE。
3. **编辑输出 diff 而非重写**：反思器输出 `Edit(old_string, new_string)`（SMCEvolve 的 SEARCH/REPLACE、LPO 的先圈区域后改），配 POaaS 式 drift cap（每个 CE 记录 D(x,x′)，超阈拒收）和 conservative skip gate。这天然限制编辑半径，也让 P 计数精确挂到被改的那条规则上。这与 SkillOpt 已确认要搬的"编辑预算硬截断"合流。
4. **P1-P18 户口本升级为 ExpeL 记账**：操作词表限定 ADD/EDIT/UPVOTE/DOWNVOTE，初始 count=2、归零即触发退役审计（我们已有"退役必须去句重跑实测"，正好当归零后的确认步）——把"删不删"从人工判断变成计数器语义+实测确认。
5. **不急着做**：batch 编辑冲突检测（无成熟文献，自研收益不明）；GEPA Pareto 前沿（单目标+11 案例的场景过重，串行接受即可）。

## 三问合一的机制闭环

```
运行时：段+假设双标签（已有）+ claim→evidence 依赖边（补）+ 段入口快照/随机源（补）
   ↓
检测：确定性 checker（receipt 统计元数据缺失即 BLOCKED）→ checklist reviewer 对结果文件 → failure_type 归类
   ↓
定位：段级粗定位（12 段候选集）→ 疑点段补丁重放（插入缺失验证步重跑下游）→ 结论翻转=因果确认
   ↓
上升：跨轨迹同环节复现 → 单条款干预（aPSF）→ blame 落到 playbook 具体规则
   ↓
编辑：diff 式最小编辑 + drift cap → 冻结集串行验证（一轮一个跨规则编辑）→ 不升回滚+DOWNVOTE
   ↓
记账：ExpeL 计数器（±1，归零触发退役审计）→ 回到运行时
```

## 补充（2026-08-31 用户提案评估）：全程 append-only 类型化 DAG 作为轨迹底座

### 提案要点（用户）

从 skill 运行第一刻起构建一张只追加不覆盖的类型化 DAG：Run → SkillSnapshot → 各 stage 产物 → H1@v0 → Intervention → Receipt → Verification → Conclusion；回退旧 stage 不覆盖而是追加新版本节点（H1@v0 → SeedCheck failed → Stage1-Retry → H1@v1），拓扑上永远无环；文件按三级建档（辅助阅读挂路径 / 决定结论建节点 / 需独立验证必须建节点，可变文件配 sha256/CAS）；边带类型（precedes/produces/consumes/informs/supports/refutes/revised_to/governed_by）；timeline/stage/episode/evidence/failure/revision 全部是同一张图的投影视图；跨 skill 版本以 Reflection→SkillEdit 节点连接各 candidate 的 run 分片，构成进化总图；失败时沿图反向定位 first divergence，截局部子图喂反思器。

### 判定：方向成立，落地形态需三处修正

**与文献的吻合**。运行时落盘+append-only = AER（2603.21692）"溯源必须运行时记录、事后从 trace 重建不忠实"的工程化；边类型词表 ≈ W3C PROV-DM（produces≈wasGeneratedBy、consumes≈used、revised_to≈wasRevisionOf）——应直接借 PROV 命名而非自创；supports/refutes 边 = evidence–claim support graph（2606.04990），正是本调研判定的第一缺项；局部子图喂反思 = REFLECT 的"正确前缀+错误步+级联窗口"，且图使窗口选择从人工圈定变成可计算（ancestors(结论,k) ∪ descendants(疑点)）。append-only 版本节点顺带解决阶段 4 两个已知缺口：ledger 回写后分不清哪句何时写、post-hoc 假设不分裂新段——图上天然是新节点，无需改状态机。"视图是投影"保证阶段 4 成果不作废：segment_id/episode_id 降级为节点属性与分组键，segments.json = Stage view 物化，迁移是加法。

**修正一：图的写入主语不能是 agent**。C1 实测凡依赖 agent 自觉报到的机制全部失灵（DECISIONS.jsonl 零条、PROGRESS.md 被整篇重写）。但关键节点本就以结构化产物形态在运行时落盘（ledger/plan/receipt/结论，有校验器）。图不需要新写入方，需要的是：① 现有 schema 补两类引用字段——`evidence_refs`（结论/判决引用哪些 receipt/图表 → supports/refutes 边原料）与 `governed_by`（本步执行哪条 playbook 规则）；② 收卷时 `graph_build.py` 把结构化产物+stage_probe 事件按 H 号/路径/sha256 **确定性 join** 成 nodes/edges——是查表不是 LLM 猜，不违反"运行时记录"原则；③ 引用字段靠校验器硬闸承重（结论无 supports 边 → conclusion_gate BLOCKED），不靠 playbook 散文提醒。探针继续补 join 够不着的三个洞（paused/闸/脚本内部产物）。

**修正二：边分两级信任**。`asserted_by: harness | agent` 必带。观测边（produces/consumes/precedes：来自文件写入、工具调用、时间戳）harness 背书可信；自报边（informs/supports/refutes/governed_by）与决策日志 rationale 同性质——可能是流畅度产物（Credit Without Ground Truth 的 +0.75 警告直接适用）。能机检的自报边就机检：supports 边指向的 receipt 其 delta 符号必须与结论方向一致，不一致即结构性矛盾——免费的错误检测器。

**修正三："有向图⇒因果分析"收窄**。CAR 不是这个逻辑——CAR 不建溯源图，因果证据完全来自 do-操作后重放测分布偏移。本提案的 DAG 是**观察性溯源结构**，两者互补：图能做的=可达性分析（污点传播：descendants(被污染节点)=作废清单；blame 候选集：ancestors(失败结论)；跨版本对齐候选窗口），全是确定性图算法；图不能做的=从拓扑推因果效应——边不完备（所有节点共享同一 LLM 上下文=图上画不出的巨大共因）、自报边可能错、consumes 只说"用了"不说"起多大作用"，backdoor adjustment 式识别不成立。因果判定唯一来源仍是补丁重放。协同红利：**某节点的 consumes 闭包（带 sha）= 从该节点重放所需的最小状态快照定义**——"段入口可重启状态"在图里免费得到。最接近此组合的文献是 STAMP（provenance-guided credit assignment）+ REFLECT，非 CAR 单篇。

### 理论可行、实际有坑的清单（按风险序）

1. **跨版本 first divergence 对齐是模糊的**：V0 的 H1 与 V1 的 H1 不必然同一条假设（H 号各 run 自编）。段级对齐稳（stage 结构固定），假设级需按内容（干预目标/组件）做等价类匹配——"首次分歧≠首错需等价类"的警告在图上依然成立，图只是把问题变清楚，没消掉它。
2. **节点膨胀**：三级建档标准必须写成 schema 硬规则，否则图退化成第二份 transcript。C1 量级预估 30–60 节点/run，可控。
3. **指令负担**：skill 已被判"太重"，新字段走校验器硬闸而非 playbook 散文（一条 REQUIRED 校验比三句提醒便宜且不可绕）。
4. **append-only 与回写的冲突已被 sha 化解**：节点引用可变文件时带 (path, selector, sha256_at_assertion)，断言时刻的 sha 冻结当时内容，之后回写不污染历史——提案 §4 的 CAS/sha 条款正确且必须。
5. **图自身的宁缺毋假纪律**：join 失败的边显式 gap+why，不许静默丢——反思会把"边不存在"读成"没有依赖"，与阶段 4 fill:gap 同族。

### 推荐路线：先离线证伪，再进 schema，分三步

**第 0 步（一天量级，零破坏）——C1 冻结数据上离线重建整张图**。产物、已回填 segments、转录俱在。验收 = C1 三个已知缺陷能否变成结构查询：① eval_H1.py 孤儿脚本 → receipt 节点缺 produced_by 入边；② receipt 不落全切片版图 → Conclusion 的 supports 闭包查不到切片表节点；③ 假想注入"H1 单 seed" → receipt 的 n_seeds 字段一跳可查，且 descendants(H1-receipt) 给出作废清单。三条全查到 → 图值得进 schema；查不到 → 缺的字段清单自动暴露。**此实验先于任何 schema 定稿**——防止先定 schema 再发现拼不出来。

**第 1 步——引用字段进产物 schema + graph_build.py 进收卷**（对应落地清单第 6 项的完整版）：evidence_refs/governed_by 两字段 + 校验器硬闸 + 确定性 join + 边信任分级。segment/episode 不动，降为投影键。

**第 2 步——图驱动的两段式反思与补丁重放**（对应落地清单第 3、7 项的合流）：失败结论 → ancestors 闭包出 blame 候选段 → 候选段子图（含高层卡片化的其余段）喂反思器 → 疑点节点的 consumes 闭包定义重放最小状态 → 补丁重放判翻转 → blame 经 governed_by 边直接落到 playbook 条款 → 接串行接受协议（落地清单第 1 项）。

与原落地优先级的关系：本路线不推翻原 1–5（循环层改动照旧先行），它把原 6–7（依赖边、补丁重放）合并升级为图底座的三步，且第 0 步可与循环层改动并行。
