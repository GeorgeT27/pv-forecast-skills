karpathy agent 的 autoresearch 每次假设都不靠推理判定，靠真跑实验判定。 看它的命中率：700 次实验只有 ~20 个真改进，97% 的尝试是错的。一个错误率 97% 的系统之所以还能产出实质结果，是因为验证成本低到可以承受海量试错。 
给 ts-diagnose 加的不是更多分析话术，是行动能力：

1. 新增一个 architecture-attribution playbook，流程强制为：误差签名 → 生成 2–3 个架构假设（联动 model-audit 读代码）→ 为每个假设设计单变量消融 → 在 demo 数据上真跑 → 用测得的 delta 确认或否证；
2. 结论闸升级一条硬规则：任何架构层因果结论必须引用一个消融 delta，引不出的只能标记为"未验证假设"。这一条就直接杀死泛化答案——模型想说"attention 导致 peak"就必须先跑出证据，说不动就只能老实说"这是假设"；
3. 你的 demo 数据小、框架可改，正是 Karpathy 场景的缩小版（他的 depth-12 就是为了让单次实验便宜到分钟级）。同样要学他的迁移验证：demo 上确认的结论，最终要在真实数据/大模型上抽查一次，防止过拟合小数据——他用 depth-12→depth-24 迁移证明改进是真的，你也需要这一步。
