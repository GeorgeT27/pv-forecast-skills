## 1. 结论三道门

**稳健性门槛 → 假设登记 → 反驳门**，缺一不可；三门全过才可在 FINDINGS.md 标「已证实」。

### 1.1 稳健性门槛（差异是不是噪声）

写"A 比 B 好 / X 段变差"之前：① 按可配对单位（天/单元/fold）做 **Wilcoxon 符号秩检验**（或 bootstrap）且显著；② **剔除最差 10%（或 3 个）极端单位**后结论方向不变。任一不过 → 改写为"差异不显著"或"差异由个别极端单位驱动"。未过门槛的比较结论比没有结论更有害。

### 1.2 假设登记（先预测后看数）

任何机制结论落 FINDINGS.md 前必须引用工作目录 `HYPOTHESES.md` 的一条 H-ID（模板：引擎 `scripts/templates/HYPOTHESES.template.md`）。命中已有条目 → 看数后更新状态与证据链接；没有 → **先新增"预注册"**（写清可判别预测：为真时应看到什么、看不到什么）再去验。这是防"看到结果再编机制故事"的闸门。

### 1.3 反驳门（差异是不是别的原因造成的）

标「已证实」前，逐条走**通用替代解释清单** + playbook 特有条目（各 playbook §反驳门节）——每条要么给出排除证据（引用具体产物数字），要么显式标"未排除"并把结论降级为「假设」：

1. **数据/解析错位**：本次对账与验证步全过了吗？覆盖有缺口吗？任一存疑 → 结论不可信，先回对应阶段。
2. **样本量不足**：涉及分组的样本数 ≥ 阈值（默认 10）吗？不足 → 只描趋势。
3. **构成变化冒充能力变化**：X 段变差是"难例占比升高"还是"同类内退化"？没拆分 → 未排除。
4. **分布外/漂移**：对比的两段数据分布可比吗？漂移未查 → 未排除。
5. **上游原料变化**：输入数据源/预处理在对比窗口内变过吗（版本、单位、供应商）？
6. **共享组件混淆**：多个对象共享上游组件时，差异可能来自共享件而非对象本体。
7. **外部事件**：对比窗口内有无运维/配置/环境事件（上下文 linked 时查其事件记录）。

走完在 ANALYSIS.md 留"反驳门记录"（哪几条已排除、凭什么、哪几条未排除导致降级）。

## 2. 多证据线一致性

playbook 声明 ≥2 条 `evidence_lines` 时：各线**独立**产出排名/方向（吃不同的原始信号，如"回归吃指标序列、梯度吃几何"），主 agent 汇总时报两两 **Spearman**；只有按 `upgrade_rule` 一致才把结论从「现象」升「假设」。不一致本身是发现——要解释（如某线效应被后续训练恢复），不要挑有利的一线报。单证据线（变体未激活）时结论上限「现象」，并在 FINDINGS 注明"仅 X 侧证据"。

## 3. 事实/解释物理隔离

事实阶段（playbook `pause_after` 的阶段）产「现象清单」：每条 = 观察 + 数字 + 来源产物，**禁机制语言**（"因为/说明/导致"都不许出现）。解释只发生在结论阶段，且要过三道门。隔离的目的：防止先有故事再挑证据。停顿点由用户点名深挖项——不要替用户决定什么重要。

## 4. 产物自足与上下文预算

- 每个落盘 JSON 带**完整数字**（曲线全量或分位数摘要+形状描述符）与生成参数，判读**只读产物**：不读 PNG（图给人看）、不读原始日志/parquet 全量（解析在脚本内流式做）。
- 每阶段独立脚本 + 落盘产物，可断点续跑；一次会话可只跑一个阶段，PROGRESS.md + orient 保证续跑无缝。
- 报告增量写（ANALYSIS/FINDINGS 每阶段追加），不留"最后一把大合成"。
- **抽样/截断必须披露**：脚本若限了 top-N/抽样窗口，summary 里写明，别让主 agent 把抽样读成全量。

## 5. FINDINGS 状态机

`现象 →（登记 H-ID + 多证据线一致）→ 假设 →（三道门全过）→ 已证实`；任何时候证据否定 → `被推翻`（保留行，不删——它防止下次再走同一条弯路）。状态词是保留字（orient 判定依赖），不要改措辞。
