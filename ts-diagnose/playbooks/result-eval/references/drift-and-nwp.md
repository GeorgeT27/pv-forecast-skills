## 一、分布漂移诊断（跨站：训练站集合 vs 留出测试站）

<!-- 2026-07-09 设定变更：旧的"训练集 2024 vs 测试集 2025 跨年对比"作废。现在训练/测试都是 2025，
     漂移是**跨站**的——训练=训练站集合 pooled（及逐站），测试=留出站（不在训练里）。-->

训练集（训练站集合 2025）不参与指标计算，它的用途是回答第一大“为什么”：**留出站是不是落在训练站没覆盖的分布里、它最像哪个训练站**。这个解释与“NWP 原料差”（见下一节）、“模型类内能力”（图#8）并列，是跨站/月度变差的三大候选解释。统计之前先把滚动窗口重建为物理连续序列（重叠的原因见项目背景说明）。

三类漂移要分开查，含义完全不同（下表里“训练分布” = 训练站集合，“测试” = 留出站）：

| 漂移类型 | 查什么 | 方法 | 查出来意味着什么 |
|---------|--------|------|----------------|
| 特征漂移 | GHI/SSRD/t2m 以及 kt、σΔ 的分布，**留出站 vs 训练站同月对比**（都是 2025） | 分位数/小提琴 + KS 或 PSI | 留出站的天气模式偏出训练站分布 → 模型在分布外，差是“没见过这个站的这种天”，不是“学错了” |
| 标签漂移 | 功率分布、日发电量、日峰值 | 同上；重点看台阶/尺度差 | 留出站功率尺度与训练站不同（装机/海拔/储能所致）→ 查 `<project-context>/stations.md`（储能站充放电改变曲线形状、留出站容量），不是模型的错 |
| 映射漂移 | 功率-辐照关系 P(power \| GHI) | 留出站 vs 训练站的功率-GHI 分箱曲线叠画 | 曲线位移或弯法变 → 站与站之间物理映射不同（高海拔高辐照、组件、限电、储能），所有模型同时受累 |

产出两张图：

- **图#11 同月分布对比图**：关键变量 × 月份的网格，**留出站 vs 训练站**的分布并排，标注 KS p 值 / PSI；stats.json 逐月含 psi/ks_p/中位数/p10/p90。
- **图#12 功率-辐照映射对比图**：留出站 vs 训练站的分箱曲线叠画，标注差异区间。

**标准命令**（`scripts/run_drift.py`；`train_set` 填训练站集合 pooled 文件、`true_label` 填留出站）：

```bash
python <skill>/scripts/run_drift.py --cols "GHI-solargis,observe_power_future"
# --cols 气象列=特征漂移、功率列=标签漂移；SSRD_pos_* / t2m_pos_* / temp solargis 按 schema 补。
# 逐站对比（找留出站最像哪个训练站）：analysis_config.json 里给 "train_stations": {站名: 路径}，
# 脚本会对每个训练站单独跑一遍 vs 留出站，输出逐站 PSI 便于排"最像→最不像"。
```

脚本做四件事：`drift_table`（逐变量逐月算 PSI/KS，写进 `drift_table.csv`）、`weather_class_drift`（天气型漂移，含 kt/σΔ 分布 + 五类占比）、画 fig11/fig12；若给了 `train_stations`，再追加一张逐站漂移表。

- **三类漂移分别对号**：`drift_table` 里的气象列 = 特征漂移、功率列 = 标签漂移；`fig12` = 映射漂移。
- **共享基准是天气型漂移的命门（跨站版本）**：`weather_class_drift` 必须用 **训练站的晴空包络与 σΔ 阈值**去给留出站分类，否则各自归一化会把“留出站整体更亮/波动更少”这类整体差异抹平。（参数 `daily_weather_class` 默认 None=各自算，只适合单站单期；跨站对比必须走 `weather_class_drift`，把训练站 GHI 传给 train。）
- **逐站是新设定下的重点**：pooled（合并）会把逐站差异抹成一个平均值，所以务必看逐站 PSI 的排序，找到留出站的**迁移锚**（最像它的训练站）和**盲区**（离它最远的训练站）。
- **结果先落 `drift_table.csv`**，PSI>0.25 的变量再进 fig11 细看；结论进 Playbook A。

结论句式（占位示例，数字为示意）：“留出站 6 月的 σΔ 分布显著偏出训练站（pooled PSI 0.34；逐站看最接近 A 站 PSI 0.12、最远离 B 站 PSI 0.51）——该月天气模式是训练站集合没覆盖的，跨站 OOD 是变差主因。”

## 二、NWP 预报误差分离（条件模块——先验证前提再启用）

思路：同一个物理时刻会在数据里出现两次——在较早那一行的未来 192 段里，它是当时的**预报值**；在较晚那一行的历史 672 段里，它是**事后记录值**。两者相减，就得到 GHI/SSRD 的预报误差序列，不需要任何额外数据。有了它，就能把功率预测误差分解成“气象原料误差”和“模型映射误差”两部分——“6 月误差掉是因为气象源掉了”这句话，从猜测变成可量化的证据。

**前提验证（首次拿到数据时执行，通过了才能启用本模块）**：

1. 任选若干物理时刻，把它在所有行里的 GHI/SSRD 取值都捞出来（不同行 = 不同提前量）。
2. 若取值随提前量变化、并在进入历史段后收敛到一个稳定值 → 说明历史段是实况回填，**模块可用**。
3. 若取值处处相同 → 说明历史段只是预报存档、不是实况，**模块作废**（这种情况 NWP 质量只能借道晴天功率做代理评估，间接得多）。
4. GHI-solargis 与 SSRD 要**分别验证**：两者来源不同（卫星产品 vs 数值预报），回填策略可能一个可用、一个不可用。

验证通过后产出**图#10**：NWP 预报误差的月度曲线（按月/按提前量聚合），与功率 RMSE 的月度曲线叠画——两条线同步上升，就是“原料坏了”的直接证据。把验证结果（可用/作废）记入 FINDINGS.md，避免以后每次重验。
