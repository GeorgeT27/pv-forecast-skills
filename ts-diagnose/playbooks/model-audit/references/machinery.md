# 建档机制（源自 project-cartographer，按光伏预测语境适配）

## 1. 置信标签（每条非平凡断言都要带）

从强到弱四级：

- ✅ 代码已证：断言指向具体实现行（`file:line`），最好还带一个可测量的量。
- 📊 数据实测：数字来自 `scripts/profile_data.py` 对真实数据文件算出的统计量，
  锚点格式 `data: <file> — <stat>`。
- 📐 理论/推导：从已声明的假设推出来的结论。几何直觉类说法（如"防专家坍缩"）默认
  只能标 📐，且必须写清推导前提。
- ⚠️ 未证/推断：找不到任何锚点。标 ⚠️ 的同时要写入 `open-questions.md`。

未知永远显式：用空字段、⚠️ 或 `<!-- 待确认 -->` 明说"不知道"，绝不用推断冒充事实。

## 2. 训练流程图四要素（pipeline.md 的核心，缺一不算完成）
1. 每个节点/边都标张量维度。维度真值从 config 或数据里取并锚定；取不到就用符号表示；
   符号也定不下来 → 写 `?` 并标 ⚠️。
2. 写具体的模型模块名，例如"带 MoBA 注意力的 Transformer 编码器"；不许写"核心模型"
   这类泛称。
3. 损失函数按名字画进图里：形式 + 系数 + `file:line`；预测和标签两条线都要流入损失节点。
4. 画全训练回路：data→forward→pred→loss→backward/optimizer，并写出优化器与关键超参。

## 3. 反造假铁律
- 不臆造张量形状：静态分析定不下来 → 标 ⚠️ 并记 open-questions；手头有数据就用
  profile_data.py 实测锚定。
- 不臆造数据统计：每个标 📊 的数字都必须来自真实文件。
- 不为叙事编推导：没有代码或材料支撑的"为什么"，只能标 📐（写清前提）或 ⚠️，不能标 ✅。
- 内部名 ≠ 论文名：`symbol-map.md` 和术语表两边都要记；对应关系不确定就写不确定。

## 4. 上下文策略（撑住大仓库）

逐模型串行处理，每处理完一个立即落盘，用 `manifest`/pointer 支持断点续跑。每个模型
只在上下文里停留一次，写完就从上下文里丢掉。运行环境有子代理时：一模型一子代理并行，
父代理只保留一份小账本做汇总；没有子代理就静默退回串行。

## 5. 自检（每次产出收尾，强制）
- 落盘后置条件：预期文件确实存在（对照 output-spec.md 的清单）。
- 锚点抽查：抽几条 ✅ 断言，打开引用的 `file:line`，确认代码确实那么写；不符 →
  降级为 ⚠️ 并记 open-questions。
- 链接完整：`[[M*]]` 这类交叉引用和符号表条目都能解析，不指空。
- 覆盖：代码里找到的模型数 vs 建档数；未触达的模型文件逐个列出，不留静默缺口。
- 无裸断言：每条非平凡陈述都带标签；标 ✅/📊 的必须带锚点。

末尾给一份简短自检报告：抽查数、通过数、降级条目、覆盖率。
