# 归因方法细节（Stage 0–2 的数学与协议 + Stage 4 阶梯 + 翻新分析）

> 编号说明：本文沿用方法并入本 playbook 之前的内部阶段编号——Stage 0（探查配对）、Stage 1（坏行定位）、Stage 1.5（ε 分解）、Stage 2（双关点名）、Stage 4（反事实阶梯）。其中 Stage 0–2 都属于 playbook 的 Stage 5；本文的 Stage 4 对应 playbook 的 Stage 6。

## 口径 → 切片映射（常量一律 import 自 data_utils，绝不本地重定义）

"口径"指行级误差怎么算。一行是一个预测窗口（192 个点），不同口径取窗口的不同切片来算这一行的误差：

| 口径 | 行级误差（Stage 1 坏行） | 特征误差切片（Stage 2） | 参与行 |
|------|--------------------------|--------------------------|--------|
| `rmse_192`（默认） | 每行全 192 点 RMSE | 全窗 `[0:192]` | 全部行 |
| `ultra_short` | 每行第 `ULTRA_SHORT_IDX`(16) 点绝对误差 | `[:ULTRA_SHORT_IDX+1]`（考核点及其前导 0–4h） | 全部行 |
| `short` | `SHORT_SLICE`([59:155]) 上 RMSE | `SHORT_SLICE` | 仅 09:00 行 |

另外附一列全 192 点的特征误差作参考（`feature_err_full192`）。这一列只供人读对照；点名判定一律用与口径匹配的切片——超出口径窗口的特征误差，不可能影响该口径的行误差。rmse_192 口径下两者恰好重合。

口径由 `config.metrics` 选择，可多选，各口径各自找各自的坏行。**2026-07-16 起用户定的考核口径是 rmse_192**：每行功率预测取全 192 点的 RMSE，再对所有行取平均看整体。ultra_short/short 不再默认跑，但保留为可选——它们业务含义不同，元凶也可能不同：一个只在 4h 内起效的特征误差会伤 ultra_short、不伤 short 的次日段，反过来也一样。

## 坏行定义（Stage 1）

坏行 = 同时满足两个条件的行：`row_error > mean(该口径全体行)` **且** `进 top --top-pct%`（默认 10）。两个条件缺一不可：

- 只用分位数：在"整体都好"的月份也会硬拉出一批假坏行；
- 只用均值：长尾分布下会圈进太多行。

数据量小时要小心：比如 short 口径只取 09:00 行，可能总共只有几十行，top 10% 只剩几行——这时跟用户确认调 `--top-pct`。CSV 落**全量排名**（用 is_bad 列标出坏行），因为 Stage 2 的 z 归一与全局相关都需要全行分布做参照。

## ε_sys/ε_res 分解（Stage 1.5，v3 起默认；feature_decompose.py）

记 ε 为特征的预报误差（逐点 `ε_f = pred − label`）。分解的目标是把 ε 拆成两部分：ε_sys（随钟点、季节等条件稳定重现的系统偏差）和 ε_res（剥掉系统偏差后剩下的波动）。

**为什么要分解**：功率模型是在有偏的预报上训练出来的，会学会补偿**稳定的系统偏差**（这叫共适应）——这部分 ε 再大也不该点名，修了它对固定模型是中性甚至有害的。反过来，纯白噪声的 ε 上游改不了，点名它是废话。真正该点名的，是"波动、可约、且与功率误差相关"的那部分。

**方法**：稳健加性回归，不用分箱法——多维分箱会稀疏、要人为定边界、还要 weather_class 标签。具体做法：对逐点的 `ε_f = pred − label`，用 Huber 岭回归（对离群点不敏感、带正则的线性回归）拟合条件均值，基函数包括：截距 + 钟点谐波(≤3 阶, cyclic) + DoY（一年内日序）谐波(≤2 阶, cyclic) + 提前期 hinge（分段线性基，df≤5）+ **每个配对特征自己的 pred 值 hinge**。天气型不用显式标签，由特征值隐式承载；own-pred 项专抓"报得越高越偏高"的乘性偏差。**回归只减条件均值，不碰条件方差**——"碎云段波动大"这类异方差结构原样留在 ε_res 里（可查 feature_decomp.json 的 res_var_front/back）。

**跨期稳定性收缩**：前段拟合、后段验证，中间留 embargo 48h = 192 步防重叠窗泄漏。收缩系数 `λ = clip(⟨ε_b,ŝ_b⟩/⟨ŝ_b,ŝ_b⟩,0,1)`：拟合出的偏差模式在后段复现得越好，λ 越接近 1、剥得越足；后段不复现（比如那只是一次性崩坏）→ λ→0，整条不剥。拟合失败/样本不足/后段为空一律 λ=0。**方向保守：宁少剥（残留点系统偏差），不过剥（把可约波动当偏差丢掉，会毁掉归因）。**

**两道分解闸（decomp=on 才生效，Stage 2 消费，缺一不可）**：

- **可约性闸**：`reducibility_frac = median(逐行 lag-1 自相关)₊²` < `reducibility_min`（默认 0.1，CLI `--reducibility-min`）→ 该特征标 `irreducible`，**不点名**。含义：ε_res 接近白噪声，上游拿它没辙。v2 占位：ε_res 形状分解（相位/幅度/爬坡——相位错和幅度错对上游的指导完全不同）。
- **洗清闸（系统偏差门，代码闸）**：`sys_frac ≥ sys_frac_max`（默认 0.85，CLI `--sys-frac-max`）→ 该特征标 `compensated`，**不点名**。**为什么必须写成显式代码闸，不能指望剥完 ε_res 后 z/ρ 自动洗清**：z 分数（`z=(fe−μ)/σ`）与 Spearman 都是**尺度不变**的统计量。一个被模型补偿的系统偏差特征，剥完之后 ε_res 的量级可能塌了几十倍（金标准 f_sys_bias 实测 11.83→0.27），但只要残影的**秩结构**没塌——哪些行大、哪些行小的排序还在——z/ρ 两关照样双过，诱饵照样被冤枉点名。所以"系统偏差高的不点名"必须显式加一道基于 `sys_frac` 的阈值闸。**真实数据提醒**：own-pred hinge 是本方法唯一可能在真实数据上悄悄过剥的地方（金标准是合成数据，暴露不了这一点）——若某特征的 `sys_frac` 反常地高、但你独立地知道它携带真实可约波动，应手动做消融复核（去掉该特征自身的 own-pred hinge 项重跑分解），而非直接采信洗清闸判定。

**作用域**：只有 feature_pairs.json 里配对成功的预报特征才有 ε 可言。未配对的列（真实观测列）没有 ε、也没有反事实语义，落进 feature_decomp.json 的 skipped_unpaired。金标准埋点：f_sys_bias（乘性稳定偏差：不分解必被冤枉，剥后必被洗清）、f_res_culprit（波动元凶：必须被点名）、f_irreducible（z/ρ 双关都过、唯独被可约性闸挡下）。缺分解产物时 feature_blame 回退到原始 ε 并标 `decomp=off`（顶层 `params.decomp` 记录 `"on"`/`"off"`）。

## 两关点名（Stage 2）

> v3 起 z 与 Spearman 都算在 ε_res 上（decomp=on 时）；共线簇也在 ε_res 向量上聚——剥掉公共的系统偏差后，虚假共线会自行消解。decomp=on 时点名还须再过上面两道分解闸（可约性 + 洗清），四关全过（z、ρ、top_k、两道分解闸）才 `blamed_topk=True`。

- **关一（行内异常）**：把该特征的误差对**全体行**的分布做 z 归一：`z = (fe − μ)/σ`（σ=0 → z=0）。归一是必须的：不同量纲的特征（W/m² vs ℃）只有归一后才可比。通过条件：`z ≥ z_hi`（默认 2.0）。
- **关二（全局相关）**：`Spearman(行误差, 特征误差)` 跨全体行 ≥ `spearman_min`（默认 0.3）。这一关专拦"特征误差大但模型不敏感"的诱饵——特征烂不等于模型信它。
- 综合分 `blame_score = z × max(ρ, 0)`；每个坏行内按分数排名，进 `top_k`（默认 3）才点名。
- 阈值全部 CLI 可调；调过默认值必须在 FINDINGS 披露——阈值敏感性属于反驳门检查项。
- **报告列**（decomp=on 时）：`feature_err`（即 ε_res，无单独的 feature_err_res 列）/ `feature_err_raw`（剥前 ε）/ `feature_err_sys`（= raw − res）/ `reducibility_frac`；`note` 三态：`""`（正常）/ `"irreducible"`（被可约性闸挡）/ `"compensated"`（被洗清闸挡）。summary 每特征另加 `global_spearman_raw`（剥前对照，用于反驳门第 9 条系统偏差门"剥前冤枉、剥后洗清"的举证）、`sys_frac`、`stability_lambda`、`reducibility_frac`。

## 共线性聚类

特征误差向量（跨行）两两 Pearson ≥ 0.8 → 归入同簇（按图的连通分量聚；常量向量不连边）。簇内成员统计上不可分——往往是同一场天气过程把它们一起带错。报告只写"簇 {A,B} 至少其一"；定罪到单个特征只有一条路：Stage 4 逐个替换（`--mode per-feature`）。

## 滚动窗一致性闸的适用边界（v2 修正）

`check_window_consistency` 检查的恒等式是"行 t 第 k 点 == 行 t+1 第 k−1 点"。它只对**物理时间的函数**成立：test 的功率真值列、feature_true 的 label 列——同一物理时刻的观测值，从哪一行看都应该一样。**predict 模型列与预报特征的未来段绝不进闸**：逐行重新起报意味着相邻两行对同一物理时刻的预测/预报本来就不同（lead time 不同），那是翻新分析的信号，不是窗口构造 bug。教训来源：早期 v1 版本把 predict 列也塞进了这道闸，在真实数据上误拦了 Stage 1。

## 翻新跳变分析（feature_revision.py，免 API，默认跑）

"翻新"指相邻两次起报对同一物理时刻给出了不同的预报值。取相邻行对 (r, r+1)（须 Δts==FREQ；真实数据有缺行，不满足的对跳过），在重叠段上对齐：**r+1 第 j 点 = r 第 j+1 点**（j∈[0,190]；权威口径 data_utils.rebuild_series——未来段从窗口起点当步开始）。

- 跳变向量 `J[j] = F[r+1][j] − F[r][j+1]`；per-pair 标量按**口径匹配切片**取 RMS——对全 191 点平均会把随时刻变化的信号洗平（金标准里 short 切片跨夜恒幅即例证）。
- 指标四个：Zsoter 式 jumpiness（RMS 跳变 / 该特征全局 std）；flip-flop 率（连续对的跳变符号来回交替的比例）；**翻新改善率**（|新−真|−|旧−真| 的负值占比：≈0.5 = 无系统性改善 = 纯噪声抖动，明显 >0.5 = 健康翻新）；特征跳变 × 模型 churn（predict 列的同构跳变）的 Spearman。
- **两关点名「翻新致不稳」**：jumpiness ≥ jumpiness_min(0.05) 且 churn Spearman ≥ spearman_min(0.3)。模型自身 churn_rel < stable_max(0.02) 时直接判「行间稳定」，无案可查。
- 文献纪律：Zsoter 等对 jumpiness/flip-flop 的研究实证了**跳变与预报误差只有弱相关**——跳变大 ≠ 拖指标。用改善率区分健康翻新与噪声抖动；升「已证实」的唯一通道 = neighbor-swap 反事实。

## 反事实协议（Stage 4·预算阶梯）

决策数学在 `cf_logic.py`（零网络，`--selfcheck` 过 gen_gate stage "4"）；runner 只做 IO/HTTP/缓存。判定**与基线调用比、而不与离线 parquet 比**：API 后面的模型版本可能与产出 predict.parquet 的版本不同，用同一次会话里的基线调用做对照可以抵消版本差。runner 同时自动做**版本漂移闸**：基线 vs 离线的行误差漂移 >20% 的行标 version_mismatch，占比 >30% 硬停。开跑前先做**确定性探针**：对首行基线重复调用 2 次，取差值上界作为 ε，进所有判定阈值——防止把服务本身的随机抖动当成修复效果。

| 层 | 每坏行调用 | 判定 |
|---|---|---|
| oracle | 2（基线+全换） | 缺口 G = base − oracle；**G 闸**：G/base ≥ g_min(0.2) 且 G ≥ 5ε，不过 =「非特征问题」，防冤枉。行集 = **全部坏行**（零点名坏行恰是非特征问题候选） |
| per-feature / all-blamed | 1+k / 1 | 边际充分性 Δ_f（v1 语义；跨层 subset 去重不重打基线） |
| minimal-set | ~p+2\|S\| | 修复谓词 R(S)=(base−err_S)/G ≥ τ(0.8)+ε/G；候选池（点名∪共线簇∪z≥1，cap 8，不足则扩全特征）**反向贪心消解**（按嫌疑升序试删+1-minimal 校验；对非单调比 ddmin 稳、顺序确定可续跑重放）。冗余结构「单换无效双换才修」在此现形 |
| lattice | 2^k（k≤5） | 每口径×模型最差 3 行：全子集精确 Shapley φ_i + 成对交互指数 φ_ij（>0 = 修复互补/冗余，≈0 = 可加） |
| neighbor-swap | ≥3/对 | 高 churn 对：r+1 的特征未来段 0..190 ← r 的 1..191（第 191 点保留原值——不在两口径切片内，零污染），churn 消减 = 翻新致不稳已证实。**须 api.neighbor_swap_confirmed**：拼接序列行间不连续，服务端若做输入连续性校验会 4xx |

判定谓词是三态的：API 失败或返回 NaN = invalid——保守地保留该特征的嫌疑，绝不当作"没修好"；替换序列含非有限值的请求不发出（json.dumps 会产出非标准的 NaN token）；考核点真值为 NaN 的行在计划期就剔除。断点续跑（resume）按 (口径,模型,行,subset_id) 做内容去重；旧版 CSV 自动迁移 schema（原文件留 .v1bak）。预算参考：设 B 个坏行、平均点名 k̄≈3、候选池 p≤8、深挖 R=3 行，则每口径×模型 ≈ 2B + k̄B + B₂(p+4) + R·2^5 ≈ 数百次调用；全量典型 800–1500 调，--max-calls 默认 400，分次跑完。

## 降级模式：窗口重叠重建特征真值（仅当用户确认没有 feature_true）

滚动窗互相重叠，这带来一个可利用的事实：行 T 未来段第 k 点对应的物理时刻是 T+kΔ，这个时刻的**观测值**会出现在其后某行 T+mΔ（m>k）的历史段第 672+k−m 位。所以可以从 test.parquet 特征列的历史段反推未来段的真值，拿来对比特征预报误差。三条限制（报告必须注明，证据自动降一级）：

- 只覆盖 test.parquet 里带 ≥672 点历史段的特征；
- 序列末尾 192 步内的行重建不全（后面没有行可借了）；
- 历史段本身若经过插值/清洗，重建出的"真值"已不是原始观测。

Stage 0 的 `label_crosscheck` 用同一机制反向核验 feature_true 的 label 列：抽样比对两个来源，agree_rate < 0.99 = 对齐错位或 label 有假，先排除再进 Stage 2。

## 时间戳对齐歧义

feature_true 的行时间戳有两种可能语义："窗口起点"或"预报起点"，两者差 672 步。probe 在 0 偏移下交集过少时会自动试 ±672 步，并把结果报在 `align_offset_steps`——非 0 时必须先跟用户确认口径，别静默平移。
