# 归因纪律 —— 从"震荡"到"已证实有害"

站点归因最大的陷阱是**把训练动力学的正常现象误当作站点的罪证**。本库定义把嫌疑站一步步升级的门槛，与 `pv-result-analysis/references/analysis-discipline.md`（结论三道门/反驳门七条）一脉相承，不重复其内容，只补本任务特有的部分。

## 状态枚举（写进 FINDINGS.md）

| 状态 | 达到条件 |
|------|---------|
| **现象** | Stage 1 回归给出 θ_s 排名（迭代 ≥10 时 CI 排除 0）。只是"数据里看到的相关"。 |
| **假设** | Stage 1 与 Stage 2（TracIn）**排名一致**（Spearman 显著为正，且该站在两法都靠前）+ Stage 3 给出可解释机制（气候距离/映射差异），并在此登记一条 H-XSTN-*。 |
| **已证实** | Stage 4 剔除该站重训，白马湖在**五口径 + Wilcoxon 门槛**上确实改善，且过反驳门。 |
| **被推翻** | 剔除重训无改善 / 或反驳门发现是数据质量、训练顺序等替代解释。 |

**跨阶段单调**：没到条件不许跳级。只有回归排名就写"已证实"是本技能头号错误。

## "震荡≠有罪"的操作化

顺序分块 + 每 chunk 20 epoch ⇒ 灾难性遗忘：训完某 chunk，模型偏向那批站的气候，对分布不同的白马湖 RMSE 可能上升——**这不是那批站"有害"，是遗忘**。区分：

- **遗忘（无害）**：某 chunk 后 RMSE 跳升，但下个 chunk（不同站）后又恢复；效应**不随特定站系统性出现**。→ 回归里该站 θ_s 不显著。
- **负迁移（有害）**：**无论**该站和谁组队、排第几，只要它在 chunk 里，白马湖 ΔRMSE 就系统性偏正。→ 回归 θ_s 显著为正 + TracIn 持续负对齐。

判据落在**回归的跨 chunk 系统性**上，不在任何单个 chunk 的跳变上。任何"看某次 RMSE 暴涨 → 归咎当时的站"的推理都要被拒绝。

## 反驳门（本任务版，标"已证实"前逐条排除）

借用七条通用替代解释，落到本任务：

1. **遗忘伪装**：ΔRMSE 冲击是否只是训练顺序/新近效应？→ 看第二因变量（新近 vs 任意位置），控制 `position` 后 θ_s 还在吗。
2. **样本量**：该站出现次数够吗（≈迭代数）？迭代 <10 一律降级。
3. **数据质量红旗**：该站气候与白马湖**相似却有害** = 强烈提示限电/坏 NWP/传感器故障，不是"分布冲突"。→ 走 pv-result-analysis 的 `run_quality_check.py` + `event-log.md` 查该站原始数据；是数据问题就**修数据**，别删站。
4. **回放错位**：assignments 过了指纹校验吗？没过 → θ_s 归错站，先修 Stage 0。
5. **单证据线**：只有回归、没有 TracIn 佐证？→ 只能停在"现象"。
6. **口径/评估错**：白马湖 RMSE 是不是用了错的 label 列/取点？→ 只用 `observe_power_future`，整体 48h RMSE，别混训练特征列。
7. **共享上游**：M1/M3/M4 共享 Chronos（见 models.md）——若"有害"只在这三个同现、M2 无感，可能是 Chronos 相关而非站相关。跨模型 Spearman 帮判。

每条给排除证据或标"未排除"并降级。记录进 `ANALYSIS.md`。

## 功效与诚实披露

- 迭代数 N 决定一切。观测 = 每模型 ~4N。**N<10：只排名**。报告里必须写出 N 与"能下什么结论"。
- 分组统计（如"该站在多云天更拖累"）先报每组样本数，<10 只描述趋势。
- 岭回归 λ 会压缩系数：报排名稳健（换 λ 排名不翻），别报被 λ 影响的绝对值。
- **silent cap 要披露**：TracIn 只取了部分 checkpoint / 每站只用 200 窗口，都要在结论里写明"覆盖范围"，别让"抽样"读成"全量"。

## Stage 4 确认协议

1. **便宜探针**：从最终 checkpoint 出发，只在单个 top 嫌疑站上短暂微调，测白马湖验证 ΔRMSE。方向对（微调它→白马湖变差）= 一阶因果信号，几分钟。
2. **决定性检验**：剔除 top 2–3 嫌疑（15–16 站）**重训一次**，与原 17 站同种子同协议，白马湖 test 五口径对比 + Wilcoxon 配对（复用 pv-result-analysis 的 metric 流水线与 `robustness_check`）。过了才升"已证实"。
3. 若剔除反而变差 → 该站其实有益/无害，推翻假设，回头查为什么前两阶段误报（多半是遗忘伪装或回放错位）。

## 面向主管的结论

同 pv-result-analysis 的 CONCLUSION 纪律：把"已证实"结论翻译成管理层语言——"X、Y 两个站（西北干旱高辐照，与白马湖平原湿润气候差异最大）系统性拉低白马湖预测，剔除后白马湖 RMSE 降低 Z%"。方法论机器（回归/TracIn/Wilcoxon）不进正文，末尾一句话说可信度。附**给未来训练的建议**：逐 chunk 组成落日志、混站 batch / 回放缓冲抑制遗忘、相似度加权采样偏向部署目标气候。
